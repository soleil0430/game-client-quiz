자료구조·알고리즘

복잡도

N이 두 배가 될 때 비용이 몇 배로 자라는지만 말한다. 실제 시간은 프로파일러로 잰다

유닛 100마리에서 멀쩡하던 충돌 검사가 1,000마리에서 프레임을 먹는다. 유닛은 10배가 됐는데 검사 비용은 100배가 됐다. 실기기에 올려 보고서야 알면 설계를 되돌리기 어렵다.

복잡도는 짜기 전에 그 100배를 미리 보는 자다.

N이 두 배가 되면 비용은 몇 배가 되나

복잡도는 입력 크기 N이 커질 때 비용이 자라는 속도다. 연산 횟수가 자라는 속도가 시간 복잡도, 추가로 쓰는 메모리가 자라는 속도가 공간 복잡도다.

빅오 표기법은 가장 빨리 자라는 항만 남긴다. 3N² + 100N + 5에서 N이 백만이 되면 N² 항 앞에서 나머지는 먼지다. 그래서 상수 배와 하위 항을 버리고 O(N²)로 쓴다.

곡선 모양이 곧 위험도다. O(log N)이 바닥에 깔리는 이유는 한 번 볼 때마다 후보가 절반으로 줄기 때문이다. 100만을 반씩 자르면 스무 번 만에 하나가 남는다.

복잡도 N이 100만일 때 대표 예
O(1) 1 배열 인덱스 접근, Dictionary 조회
O(log N) 20 이진 탐색, 균형 트리 조회
O(N) 100만 전체 순회, 선형 탐색
O(N log N) 2천만 비교 기반 정렬
O(N²) 1조 모든 쌍을 도는 이중 루프
O(2ⁿ) 사실상 불가 부분집합 전수 탐색

O(N²)가 프레임 예산을 넘는 지점

가장 흔한 O(N²)는 모든 쌍을 도는 이중 루프다. 유닛끼리 충돌을 검사하는 코드가 그렇다. 비교 횟수가 유닛 수에 어떻게 매달리는지 보자: 

// N마리를 모두 짝지으면 N(N-1)/2번 — O(N²)
for (int i = 0; i < units.Count; i++)
    for (int j = i + 1; j < units.Count; j++)   // 자기 뒤쪽만 본다
        CheckCollision(units[i], units[j]);

100마리면 4,950쌍이라 60fps에서도 버틴다. 1,000마리면 약 50만 쌍이 되어 한 프레임 예산 16.7ms를 넘긴다. 유닛은 10배, 비용은 100배다.

여기서 루프를 아무리 다듬어도 소용이 없다. 격자나 쿼드트리로 공간을 나눠 가까운 것끼리만 비교하면 비교 횟수 자체가 준다. 복잡도를 낮춘다는 말은 이런 뜻이다.

빅오가 같아도 실측은 갈린다

빅오는 증가 추세만 말한다. 상수 배와 하위 항을 버렸으니, N이 작을 때는 복잡도가 나쁜 쪽이 이기기도 한다.

원소 네다섯 개짜리 목록이 그렇다. 해시를 계산하고 버킷을 찾아가는 Dictionary보다 배열을 그냥 훑는 쪽이 빠르다.

같은 O(N log N) 정렬끼리도 실측은 몇 배씩 갈린다. 캐시 지역성과 분기 예측이 다르기 때문이다. 복잡도는 설계를 고를 때 쓰는 자이고, 진짜 시간은 프로파일러로 재는 값이다.

가끔 비싼 연산은 나눠 갚는다

List<T>.Add는 내부 배열이 꽉 찬 순간에만 O(N) 복사를 한다. 그럼 Add의 복잡도는 O(N)인가.

아니다. 그 복사는 용량이 두 배로 늘 때만 일어나 갈수록 드물어진다. 여러 번 호출한 비용을 평균 내면 Add 한 번은 O(1)이고, 이렇게 평균 낸 값을 분할 상환 복잡도라고 한다.

최악이 O(N)이라고 평균까지 O(N)인 것은 아니다.

면접에서 이렇게 답한다

  • 시간 복잡도와 공간 복잡도란 — 입력이 커질 때 연산 횟수와 추가 메모리가 각각 얼마나 빨리 느는지를 나타낸 값이다. 빅오는 가장 빨리 자라는 항만 남긴다. 그래서 규모가 커졌을 때의 우열을 가리는 데 쓴다고 정리한다.
  • O(1)이 항상 O(N²)보다 빠른가 — 아니다. 상수 배를 버린 값이라 입력이 작으면 순위가 뒤집힌다. 원소가 네다섯 개면 해시 계산 비용이 더 커서 선형 탐색이 이긴다고 예를 들고, 최종 판단은 실기기 프로파일링으로 한다고 덧붙인다.
  • 시간과 공간 중 무엇을 택하나 — 모바일은 메모리 한도가 먼저 걸린다. 미리 계산해 표로 캐시하기 전에 그 표가 먹는 용량과 아끼는 프레임 시간을 같이 본다고 답한다.

이런 오해를 한다

  • “빅오를 보면 실행 시간을 안다” — 나오는 것은 증가 추세뿐이다. 같은 O(N)짜리 두 코드의 실측이 10배 벌어지는 일은 흔하다.
  • “복잡도가 같으면 성능도 같다” — 메모리 접근 패턴이 다르면 캐시 적중률에서 몇 배가 갈린다.
  • “상수 배는 무시해도 된다” — 이론에서 버리는 것이지 코드에서 버리는 것이 아니다. 매 프레임 도는 루프의 2배는 그대로 2배 비용이다.
  • “최악이 O(N)이면 평균도 O(N)” — 동적 배열 확장처럼 드문 비용은 나눠 갚으면 O(1)이 된다.

3줄 정리

  • 빅오는 N이 커질 때 비용이 자라는 속도만 말한다
  • O(N²)는 N이 10배면 100배다. 루프 말고 구조를 바꾼다
  • 같은 복잡도끼리의 우열은 프로파일러가 가린다
