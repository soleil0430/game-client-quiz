자료구조·알고리즘

스택·큐·우선순위 큐

꺼내는 순서 규칙 하나가 자료구조를 가른다. 기능을 줄인 대가로 모두 O(1)이다

UI 팝업은 언제나 맨 위에 뜬 것부터 닫혀야 한다. 스폰 대기열은 먼저 신청한 유닛이 먼저 나와야 한다. 둘 다 규칙이 순서 하나뿐인데, 리스트에는 그 규칙이 없다.

자료구조가 대신 지켜 주지 않으면 인덱스를 손으로 관리하다 언젠가 한 칸씩 어긋난다.

할 수 있는 일을 줄여 순서를 보장한다

스택과 큐는 저장 방식이 아니라 꺼내는 순서 규칙으로 정의된다. 스택은 마지막에 넣은 것을 먼저 꺼내고(후입선출, LIFO), 큐는 먼저 넣은 것을 선입선출로 꺼낸다(FIFO). 배열로도 연결 리스트로도 만들 수 있고, 규칙만 지키면 속은 무엇이든 된다.

대신 가운데 원소 접근은 어느 쪽도 지원하지 않는다. 할 수 있는 일을 줄인 대가로 모든 연산이 O(1)이다. 타입 이름만 봐도 여기서는 이 순서로만 쓴다는 의도가 읽히는 것은 덤이다.

구조 꺼내는 순서 게임에서 쓰는 곳
스택 가장 최근 것 UI 팝업과 뒤로 가기, 실행 취소, DFS
큐 가장 오래된 것 스폰 대기열, 입력 버퍼, 순차 로딩, BFS
우선순위 큐 우선순위가 높은 것 A* 열린 목록, 쿨다운 타이머, 스케줄러

게임 밖에서도 같은 규칙이 보인다. 함수 호출 기록과 실행 취소, DFS가 스택이고 네트워크 패킷 버퍼가 큐다. BFS의 방문 대기열도 마찬가지다.

배열로 만든 큐도 Dequeue가 O(1)이다

C#의 Stack<T>와 Queue<T>는 속이 배열이다. 특히 Queue<T>는 원형 버퍼다. 머리와 꼬리 인덱스가 배열 끝에 닿으면 0으로 감아 돈다.

덕분에 Dequeue가 뒤 원소를 당기는 O(n) 작업이 아니라 머리 인덱스를 한 칸 옮기는 O(1) 작업이 된다. 연결 리스트로 만들어도 O(1)이지만, 그쪽은 원소마다 노드를 할당해 GC를 건드린다.

스택 두 개로 큐를 만들 수 있을까

된다. 뒤집기를 두 번 하면 원래 순서로 돌아온다는 성질을 쓴다. 넣기용과 꺼내기용 스택을 따로 두고, 언제 옮기느냐가 전부인 문제다: 

public class QueueByStacks<T>
{
    readonly Stack<T> _in = new Stack<T>();
    readonly Stack<T> _out = new Stack<T>();

    public void Enqueue(T item) => _in.Push(item);

    public T Dequeue()
    {
        if (_out.Count == 0)          // 비었을 때만 통째로 옮긴다
            while (_in.Count > 0)
                _out.Push(_in.Pop());
        return _out.Pop();
    }
}

규칙은 하나다. 꺼내기용 스택이 비었을 때만 넣는 쪽을 통째로 옮긴다. 넣기용을 조금씩 흘려보내지 않는다.

두 번 뒤집히면서 순서가 선입선출로 바로잡히고, 원소마다 옮겨지는 횟수가 한 번뿐이라 분할 상환하면 O(1)이다. 호출할 때마다 옮기면 매번 O(N)이 되어 이득이 통째로 사라진다.

우선순위 큐는 힙으로 만든다

우선순위 큐는 넣은 순서와 무관하게 우선순위가 가장 높은 것부터 꺼내는 큐다. 정렬된 리스트로 만들면 꺼내기는 O(1)인데 삽입이 O(N)으로 튄다.

보통은 이진 힙으로 만든다. 최솟값은 늘 루트에 있으니 조회가 O(1)이고, 삽입과 최솟값 꺼내기가 각각 O(log N)에 끝난다.

부모가 자식보다 작기만 하면 되므로 전체가 정렬된 것은 아니어서, 배열을 그대로 순회해도 정렬 순서가 나오지 않는다.

C#은 .NET 6부터 PriorityQueue를 표준으로 제공한다. 내부는 배열 기반 4진 최소 힙이다. 다만 Unity 2022 LTS의 API 호환성 수준에는 이 타입이 없어, 이진 힙을 직접 쓰거나 패키지를 가져다 쓴다.

면접에서 이렇게 답한다

  • 스택과 큐의 차이와 활용 — 스택은 후입선출, 큐는 선입선출이다. UI 팝업을 쌓았다가 뒤에서부터 닫는 흐름은 스택으로, 스폰 대기열과 순차 로딩은 큐로 잡았다고 예를 든다. 둘 다 가운데 접근을 막는 대신 모든 연산이 O(1)이다.
  • 스택 두 개로 큐 만들기 — 넣기용과 꺼내기용 스택을 둔다. 꺼내기용이 비었을 때만 전부 옮기면 두 번 뒤집혀 순서가 바로잡힌다. 원소당 이동이 한 번이라 나눠 갚으면 O(1)이라는 데까지 말한다.
  • 우선순위 큐란 — 우선순위가 높은 원소부터 꺼내는 큐다. 보통 이진 힙으로 만들어 삽입과 삭제가 O(log N)이다. A*의 열린 목록이 대표 사례이고, Unity 기본 런타임에는 PriorityQueue가 없어 직접 구현했다고 덧붙인다.

이런 오해를 한다

  • “우선순위 큐를 순회하면 우선순위 순으로 나온다” — 힙은 부모가 자식보다 앞선다는 부분 순서만 지킨다. UnorderedItems라는 이름이 그대로 말해 준다.
  • “우선순위 큐는 정렬된 리스트다” — 그렇게 만들면 삽입이 O(N)이다. 힙은 전체 정렬을 포기해 삽입을 O(log N)으로 낮춘 구조다.
  • “배열로 만든 큐는 Dequeue가 O(N)” — 원형 버퍼로 머리 인덱스만 옮기면 O(1)이다.
  • “스택 두 개 큐는 꺼낼 때마다 옮긴다” — 매번 옮기면 호출마다 O(N)이라 만든 의미가 없다.

3줄 정리

  • 스택·큐는 꺼내는 순서 규칙으로 정의된 구조다
  • 기능을 줄인 대가로 모든 연산이 O(1)이 된다
  • 우선순위 큐는 힙으로 만들어 O(log N)에 맞춘다
