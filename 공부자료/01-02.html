객체지향 문법

부르는 쪽이 구체 타입을 모르게 하는 장치와 가상 메서드 표의 원리

적 100마리를 도는 루프에서 타입마다 if를 쓰면 어떻게 되나. 새 몬스터를 하나 추가할 때마다 그 루프를 찾아 고쳐야 한다. 상속과 인터페이스, 가상 메서드는 이 수정을 없애려고 있다.

타입이 늘 때마다 루프를 고치지 않으려면

목표는 하나다. 부르는 쪽이 구체 타입을 모른 채 일을 시키게 만드는 것이다. Attack()을 시킬 때 슬라임인지 보스인지 알 필요가 없어야 한다.

고르는 기준도 간단하다. 물려줄 상태와 기본 구현이 있으면 추상 클래스다. 상속 계층이 다른 타입들이 같은 약속만 지키면 되면 인터페이스다.

C#은 클래스 다중 상속을 막는다. 같은 멤버를 양쪽에서 물려받는 다이아몬드 문제를 피하기 위해서다. 대신 인터페이스는 여러 개 구현할 수 있다.

구현할 두 인터페이스에 이름이 같은 메서드가 있을 수 있다. 이때는 명시적 인터페이스 구현(void IA.Attack())으로 각각 따로 정의한다.

가상 메서드 표가 실제 타입의 구현을 찾아 준다

부모 타입 변수로 불러도 자식 구현이 실행되는 데는 이유가 있다. 타입마다 가상 메서드 표가 하나씩 있기 때문이다. 호출이 그 표를 한 번 더 거쳐 실제 구현으로 간다.

override는 이 표의 칸을 덮어쓴다. 그래서 변수 타입이 무엇이든 실제 객체의 구현으로 간다. new는 표를 건드리지 않고 이름만 가려 다형성이 끊긴다.

override와 new를 같은 자리에서 비교한 코드다: 

class Enemy { public virtual void Attack() => Debug.Log("적"); }
class Boss  : Enemy { public override void Attack() => Debug.Log("보스"); }
class Slime : Enemy { public new      void Attack() => Debug.Log("슬라임"); }

Enemy a = new Boss();
Enemy b = new Slime();
a.Attack();   // 보스 - override라 실제 객체 타입의 구현이 불린다
b.Attack();   // 적   - new라 변수 타입 기준으로 불린다

결정 시점이 다른 오버로딩과 오버라이딩

오버로딩은 같은 이름에 매개변수 구성을 다르게 둔 것이다. 어느 것을 부를지는 컴파일 시점에 정해진다. 반환 타입은 판별에 쓰이지 않는다.

오버라이딩은 실행 중에 실제 타입을 보고 정해진다. 그래서 같은 한 줄이 객체에 따라 다르게 동작한다.

static 생성자도 시점 이야기다. 그 타입을 처음 쓰는 시점에 런타임이 딱 한 번 부른다. 호출 시점을 프로그래머가 정할 수 없으므로 무거운 초기화를 넣지 않는다.

합집합인 protected internal, 교집합인 private protected

한정자 접근할 수 있는 곳
protected 어셈블리와 무관하게 파생 클래스
protected internal 같은 어셈블리 전체 + 다른 어셈블리의 파생 클래스 (합집합)
private protected 같은 어셈블리 안의 파생 클래스만 (교집합)

제네릭 제약은 반대로 범위를 좁혀 얻는다. where T : IDamageable은 컴파일러에게 T가 적어도 무엇을 하는지 알려 준다. 그래서 캐스팅 없이 그 멤버를 쓸 수 있다.

면접에서 이렇게 답한다

  • 인터페이스와 추상 클래스 중 무엇을 쓰나 — 공통 상태와 기본 동작을 물려줄 것이 있으면 추상 클래스다. 상속 계층이 다른 타입들이 같은 기능을 약속하게 하려면 인터페이스다. C#은 클래스 상속이 하나뿐이라 확장 지점은 인터페이스로 여는 편이 안전하다.
  • 가상 메서드는 어떻게 동작하나 — 타입마다 가상 메서드 표가 있고 호출이 그 표를 거쳐 실제 구현으로 간다. 간접 호출이라 아주 약간 느리다. 더 재정의할 일이 없으면 sealed를 붙여 최적화 여지를 준다.
  • 오버로딩과 오버라이딩의 차이 — 오버로딩은 이름이 같고 매개변수가 다른 메서드를 여러 개 두는 것이다. 컴파일 시점에 결정된다. 오버라이딩은 상속 관계에서 가상 메서드를 다시 구현하는 것이고 실행 중에 결정된다.
  • 상속은 허용하되 재정의만 막으려면 — 그 메서드를 sealed override로 선언한다. sealed class는 상속 자체를 막아 조건을 넘어선다.

이런 오해를 한다

  • new로 재정의해도 override와 결과가 같다 — new는 가리기일 뿐이다. 부모 타입 변수로 부르면 부모 구현이 실행된다.
  • protected internal은 같은 어셈블리의 파생 클래스만 — 그것은 private protected다. protected internal은 합집합이라 같은 어셈블리면 상속 관계가 아니어도 접근된다.
  • 반환 타입만 다르면 오버로딩이 된다 — 오버로딩 판별에 반환 타입은 쓰이지 않는다. 그대로 컴파일 오류가 난다.
  • 인터페이스는 구현을 전혀 가질 수 없다 — C# 8부터 기본 구현을 넣을 수 있다. Unity는 2021.2 이후 C# 9 기준이다. 다만 인스턴스 필드는 못 가지므로 상태를 물려주려면 추상 클래스가 필요하다.
  • 어트리뷰트를 붙이면 코드가 실행된다 — 어트리뷰트는 메타데이터일 뿐이다. 그것을 리플렉션으로 읽는 쪽이 동작을 바꾼다.

3줄 정리

  • 상속과 인터페이스는 부르는 쪽이 타입을 모르게 하는 장치
  • override는 가상 메서드 표를 덮어쓰고 new는 이름만 가린다
  • 오버로딩은 컴파일 시점, 오버라이딩은 실행 중에 정해진다
