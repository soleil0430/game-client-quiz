정렬과 탐색

정렬은 최악·추가 공간·안정성으로 고른다. 정렬해 두면 탐색이 O(log N)이다

랭킹 100만 명에서 특정 점수 구간만 뽑아야 한다. 정렬 없이 하면 질의마다 전체를 훑는다. 한 번 정렬해 두면 그 뒤의 탐색이 스무 번으로 끝난다.

정렬은 속도가 아니라 최악·공간·안정성으로 고른다

비교로만 정렬하면 아무리 잘해도 O(N log N)보다 빠를 수 없다. 그래서 무엇이 더 빠른지는 선택 기준이 되지 못한다.

실제로 갈리는 것은 셋이다. 최악일 때 어떻게 되는지, 추가 메모리를 얼마나 쓰는지, 같은 값의 순서를 지키는지다.

정렬 평균 최악 추가 공간 안정
퀵 O(N log N) O(N²) O(log N) 아니다
병합 O(N log N) O(N log N) O(N) 그렇다
힙 O(N log N) O(N log N) O(1) 아니다
삽입 O(N²) O(N²) O(1) 그렇다
계수 O(N + K) O(N + K) O(K) 그렇다

퀵이 O(N²)가 되는 경우와 인트로 정렬

퀵 정렬은 피벗으로 작은 쪽과 큰 쪽을 나눈 뒤 각각을 다시 정렬한다. 분할이 반씩 되면 재귀 깊이가 log N이다. 매번 한쪽으로 쏠리면 깊이가 N이 되어 O(N²)다.

이미 정렬된 배열에서 첫 원소를 피벗으로 삼는 소박한 구현이 정확히 그 경우다. 그래서 무작위 피벗이나 세 값의 중간값을 쓴다.

실무 라이브러리는 인트로 정렬로 최악을 막는다. 퀵으로 시작해 재귀가 깊어지면 힙으로, 구간이 작아지면 삽입으로 갈아탄다. 마지막이 삽입인 이유는 거의 정렬된 입력에서 삽입 정렬이 O(N)에 수렴하기 때문이다.

안정 정렬이 필요한 순간

안정 정렬은 비교 기준이 같은 원소들의 원래 순서를 지킨다. 여러 기준으로 차례차례 정렬할 때 필요하다.

랭킹 화면이 그렇다. 이름순 목록을 점수순으로 다시 정렬하면서 동점자의 이름순을 지켜야 한다면 안정 정렬이어야 한다.

C#의 Array.Sort와 List<T>.Sort는 인트로 정렬이라 제자리이고 불안정하다. LINQ의 OrderBy는 안정이지만 새 시퀀스를 만들어 할당이 생긴다. 매 프레임 도는 코드면 이 할당이 그대로 GC 부담이다.

이진 탐색은 값보다 경계를 묻는다

정렬돼 있으면 이진 탐색으로 O(log N)에 찾는다. 2의 20제곱이 약 104만이라 100만 개도 스무 번이면 된다.

면접에서는 값 하나보다 경계를 묻는다. lower bound는 찾는 값 이상인 첫 위치, upper bound는 그 값을 초과하는 첫 위치다. 둘의 차이가 그 값의 개수다.

값이 없어도 끼워 넣을 자리를 돌려주므로 실패 표시가 아니다. 구현은 반열린 구간을 쓰는 쪽이 경계 실수를 줄인다: 

// value 이상인 첫 위치. 없으면 끼워 넣을 자리를 돌려준다
public static int LowerBound(int[] sorted, int value)
{
    int lo = 0, hi = sorted.Length;          // [lo, hi) 반열린 구간
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;        // (lo + hi) / 2는 오버플로 위험
        if (sorted[mid] < value) lo = mid + 1;
        else hi = mid;                       // <= 로 바꾸면 upper bound
    }
    return lo;
}

면접에서 이렇게 답한다

  • 퀵 정렬과 최악 — 피벗으로 나눠 재귀로 정렬하고 평균 O(N log N)이다. 분할이 한쪽으로 쏠리면 재귀 깊이가 N이 되어 O(N²)다. 무작위 피벗으로 피하고, 실무 구현은 인트로 정렬로 최악을 O(N log N)에 묶는다.
  • 퀵과 병합 중 무엇을 쓰나 — 메모리에 올라가는 배열이면 제자리로 돌고 캐시 효율이 좋은 퀵 계열을 쓴다. 최악을 보장해야 하거나 안정 정렬이 필요하면 O(N) 추가 공간을 쓰더라도 병합을 쓴다.
  • lower bound와 upper bound — 각각 값 이상인 첫 위치와 값을 초과하는 첫 위치다. 둘의 차이가 그 값의 개수다. 둘 다 이진 탐색이라 O(log N)이다.

이런 오해를 한다

  • 퀵 정렬은 항상 O(N log N)이다 — 피벗이 쏠리면 O(N²)다. 평균과 최악을 나눠 말한다.
  • List.Sort는 안정 정렬이다 — 불안정이다. 같은 키의 순서가 필요하면 OrderBy를 쓰거나 비교자에 두 번째 기준을 넣는다.
  • 거의 정렬된 데이터에도 퀵이 낫다 — 삽입 정렬이 O(N)에 수렴하고, 소박한 퀵은 오히려 최악이 된다.
  • lower bound는 값이 없으면 -1을 준다 — 끼워 넣을 자리를 준다. 실제로 있는지는 그 위치의 값을 봐야 안다.

3줄 정리

  • 비교 정렬은 O(N log N)이 한계다. 최악과 안정성으로 고른다
  • 퀵은 쏠리면 O(N²). 실무 구현은 인트로 정렬이다
  • 이진 탐색은 값이 아니라 경계를 구하는 도구다
