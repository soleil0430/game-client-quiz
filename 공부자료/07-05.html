자료구조·알고리즘

트리와 힙

전체 순서를 지키는 트리와 최솟값만 지키는 힙. 무엇을 포기했는지가 다르다

쿨다운이 끝난 버프를 찾겠다고 매 프레임 버프 목록 전체를 훑는다. 정작 필요한 것은 가장 빨리 끝나는 것 하나뿐이다.

전부 정렬해 두면 삽입이 비싸고, 정렬을 안 하면 찾기가 비싸다. 트리와 힙은 이 저울에서 서로 다른 쪽을 골랐다.

비교마다 절반을 버리는 이진 탐색 트리

이진 탐색 트리는 왼쪽 < 부모 < 오른쪽 규칙을 모든 노드에서 지키는 트리다. 값을 찾을 때 비교 한 번으로 한쪽 가지를 통째로 버린다.

탐색·삽입·삭제 비용이 트리 높이에 비례하는 이유다. 균형이 잡히면 높이가 log N이니 O(log N)이 된다. 중위 순회하면 언제나 오름차순으로 나온다.

정렬된 입력을 넣으면 트리가 선이 된다

균형은 저절로 잡히지 않는다. 1, 2, 3, 4, 5를 순서대로 넣어 보라. 매번 오른쪽으로만 자식이 붙어 높이가 n인 편향 트리가 되고, 탐색과 삽입이 O(n)으로 떨어진다. 이름만 트리고 사실상 연결 리스트다.

정렬된 데이터를 넣는 일은 흔하다. 실제 라이브러리가 균형 트리를 쓰는 이유가 그것이다. 레드-블랙 트리나 AVL 트리 같은 균형 이진 탐색 트리는 삽입·삭제 뒤 색 변경과 회전으로 높이를 O(log N)으로 유지한다.

회전이 한쪽으로 치우친 외줄이 되어 버리는 일을 막는다. 덕분에 정렬된 데이터를 넣어도 치우치지 않고 높이를 log N 수준에 묶어 둔다.

레드-블랙 트리는 AVL보다 균형 조건이 느슨해 회전 횟수가 적으므로 삽입·삭제가 잦은 곳에 유리하고, AVL은 더 낮은 높이를 유지해 조회가 많은 곳에 유리하다. 변경이 잦은 범용 컨테이너가 레드-블랙 쪽인 이유다. C#의 SortedDictionary와 SortedSet이 레드-블랙 트리 기반이다.

힙은 전체 정렬을 포기하고 최솟값만 지킨다

힙은 목적이 다르다. 부모가 자식보다 작거나 같다는 조건만 지키는 완전 이진 트리라, 루트가 최솟값이고 조회는 O(1)이다. 형제끼리 순서나 전체 정렬은 보장하지 않는 대신 유지가 싸다.

삽입과 최솟값 삭제는 둘 다 O(log N)이다. 삽입은 맨 끝에 넣고 부모와 비교하며 위로 올리며, 삭제는 루트를 빼고 마지막 원소를 올려 아래로 내리므로 각각 높이만큼만 움직인다.

그럼 힙에서 아무 값이나 찾으면 어떨까. 전체 정렬을 보장하지 않아 임의 값 탐색은 O(N)이다. 힙이 보장하는 것은 최솟값 하나뿐이고, 이 구조가 우선순위 큐의 기본 구현이다.

힙은 완전 이진 트리라 중간에 빈칸이 없다. 마지막 레벨을 뺀 모든 레벨이 꽉 차고 마지막 레벨은 왼쪽부터 채워진다는 뜻이다. 빈칸이 없어 포인터 없이 배열만으로 트리를 표현할 수 있다.

0번부터 채우면 i번째 원소의 자식은 2i + 1과 2i + 2에 있고, 부모는 (i - 1) / 2다. 1번부터 채우면 자식이 2i, 2i + 1, 부모가 i / 2로 더 깔끔해서 그렇게 쓰기도 한다.

배열에 저장하면 참조가 없으니 메모리도 덜 먹고, 연속 배치 덕분에 캐시에도 잘 맞는다. 삽입은 끝에 넣고 부모와 비교하며 올라가는 것이 전부다: 

static void Push(List<int> heap, int value)
{
    heap.Add(value);                 // 완전 이진 트리의 마지막 자리
    int i = heap.Count - 1;
    while (i > 0)
    {
        int parent = (i - 1) / 2;    // 배열 인덱스로 부모를 바로 얻는다
        if (heap[parent] <= heap[i]) break;
        (heap[i], heap[parent]) = (heap[parent], heap[i]);
        i = parent;
    }
}

정렬 순회가 필요하면 트리, 최솟값만 필요하면 힙

구조 조회 삽입·삭제 정렬 순회
Dictionary 평균 O(1) 평균 O(1) 불가
SortedDictionary O(log N) O(log N) 가능
SortedList O(log N) O(N) 가능, 인덱스도
이진 힙 최솟값만 O(1) O(log N) 불가

문자열에는 트라이가 따로 있다. 트라이는 문자열을 문자 하나씩 간선으로 쪼개 저장하는 트리라, 접두사를 공유하는 단어를 한 경로로 모은다.

길이 L인 문자열 탐색이 전체 단어 수와 무관하게 O(L)이다. 그래서 채팅 입력에서 접두사로 단어를 자동 완성할 때, 사전 검색, 금칙어 필터에 쓴다. 대신 노드마다 자식 배열을 들고 있어 메모리를 많이 먹는 것이 단점이다.

면접에서 이렇게 답한다

  • 이진 탐색 트리와 복잡도 — 왼쪽 < 부모 < 오른쪽 규칙 덕에 비교마다 한쪽을 버려 높이에 비례하는 비용이 든다. 균형이면 O(log N)이고, 정렬된 순서로 넣으면 치우쳐 O(n)까지 간다. 그래서 라이브러리는 회전으로 높이를 묶는 균형 트리를 쓴다고 이어 말한다.
  • 힙의 구조와 삽입·삭제 — 부모가 자식보다 작은 완전 이진 트리다. 삽입은 끝에 넣고 위로 올리고, 삭제는 루트를 빼고 마지막 원소를 올려 내려 둘 다 O(log N)이다. 빈칸이 없어 배열로 저장하고 자식이 2i+1, 2i+2라는 것까지 붙인다.
  • 힙과 이진 탐색 트리의 차이 — 힙은 최솟값만 빠르게 주는 부분 순서 구조다. 이진 탐색 트리는 전체 순서를 유지해 정렬 순회와 범위 질의가 된다.

이런 오해를 한다

  • “힙은 정렬된 구조다” — 지키는 것은 부모-자식 관계뿐이다. 배열을 그대로 출력해도 정렬 순서가 아니다.
  • “이진 탐색 트리는 항상 O(log N)” — 균형을 맞추는 트리만 그렇다. 균형 로직이 없으면 정렬 입력에서 O(n)이 된다.
  • “힙에서 특정 값 찾기도 O(log N)” — 보장되는 것은 최솟값 경로뿐이라 임의 탐색은 O(N)이다.
  • “완전 이진 트리는 모든 레벨이 꽉 찬 트리” — 그건 포화 이진 트리다. 완전 이진 트리는 마지막 레벨만 왼쪽부터 채워지면 된다.
  • “정렬이 필요하면 무조건 SortedDictionary” — 삽입이 드물고 순회가 많으면 배열 기반 SortedList가 메모리와 캐시에 낫다.

3줄 정리

  • 트리는 전체 순서, 힙은 최솟값만 지킨다
  • 균형을 안 맞추면 정렬 입력에서 O(n)이 된다
  • 힙은 빈칸이 없어 배열로 쓴다. 자식은 2i+1, 2i+2
