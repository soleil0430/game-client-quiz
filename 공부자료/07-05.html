자료구조·알고리즘

트리와 힙

전체 순서를 지키는 트리와 최솟값만 지키는 힙. 무엇을 포기했는지가 다르다

쿨다운이 끝난 버프를 찾으려고 매 프레임 전체 목록을 훑고 있다. 정작 필요한 것은 "가장 빨리 끝나는 것 하나"뿐이다. 전부 정렬해 두면 삽입이 비싸고, 안 하면 찾기가 비싸다.

비교마다 절반을 버리는 이진 탐색 트리

이진 탐색 트리는 왼쪽 < 부모 < 오른쪽 규칙을 모든 노드에서 지키는 트리다. 값을 찾을 때 비교마다 한쪽 가지를 통째로 버릴 수 있다.

그래서 탐색·삽입·삭제 비용이 트리 높이에 비례한다. 균형이 잡히면 높이가 log N이라 O(log N)이다. 중위 순회하면 언제나 오름차순이 나온다.

정렬된 입력을 넣으면 트리가 선이 된다

균형은 저절로 잡히지 않는다. 1, 2, 3, 4, 5를 순서대로 넣으면 오른쪽 자식으로만 붙는다. 높이가 n인 편향 트리가 되어 사실상 연결 리스트다.

정렬된 데이터를 넣는 일은 흔해서 실제 라이브러리는 균형 트리를 쓴다. 레드-블랙 트리는 색 변경과 회전으로 높이를 log N에 묶는다. AVL 트리는 좌우 높이 차를 1 이하로 유지해 조회가 빠른 대신 회전이 잦다.

그래서 변경이 잦은 범용 컨테이너는 레드-블랙 트리를 쓴다. C#의 SortedDictionary와 SortedSet이 그 예다.

힙은 전체 정렬을 포기하고 최솟값만 지킨다

힙은 목적이 다르다. 부모가 자식보다 작거나 같다는 조건만 지키고 형제끼리 순서는 보지 않는다. 전체 정렬을 포기한 대가로 유지가 싸다.

루트가 최솟값이라 조회는 O(1)이다. 삽입은 끝에 붙인 뒤 위로 올리고, 삭제는 루트 자리에 마지막 원소를 올려 내린다. 둘 다 O(log N)이다. 대신 임의 값 찾기는 전체를 훑어 O(N)이다.

힙은 완전 이진 트리라 중간에 빈칸이 없다. 마지막 레벨을 뺀 모든 레벨이 꽉 차고 마지막 레벨은 왼쪽부터 채워진다는 뜻이다. 덕분에 참조 없이 배열로 표현한다.

참조가 없으니 메모리도 적고 연속 배치라 캐시에도 잘 맞는다. 삽입은 끝에 넣고 부모와 비교하며 올라가는 것이 전부다: 

static void Push(List<int> heap, int value)
{
    heap.Add(value);                 // 완전 이진 트리의 마지막 자리
    int i = heap.Count - 1;
    while (i > 0)
    {
        int parent = (i - 1) / 2;    // 배열 인덱스로 부모를 바로 얻는다
        if (heap[parent] <= heap[i]) break;
        (heap[i], heap[parent]) = (heap[parent], heap[i]);
        i = parent;
    }
}

정렬 순회가 필요하면 트리, 최솟값만 필요하면 힙

구조 조회 삽입·삭제 정렬 순회
Dictionary 평균 O(1) 평균 O(1) 불가
SortedDictionary O(log N) O(log N) 가능
SortedList O(log N) O(N) 가능, 인덱스도
이진 힙 최솟값만 O(1) O(log N) 불가

문자열에는 트라이가 따로 있다. 문자 하나씩 간선으로 쪼개 접두사를 공유하는 단어를 한 경로에 모은다. 길이 L인 탐색이 단어 수와 무관하게 O(L)이라 자동 완성과 금칙어 필터에 쓰고, 노드마다 자식 목록을 들어 메모리를 많이 먹는다.

면접에서 이렇게 답한다

  • 이진 탐색 트리와 복잡도 — 왼쪽 < 부모 < 오른쪽 규칙 덕에 비교마다 한쪽을 버려 높이에 비례하는 비용이 든다. 균형이면 O(log N)이고, 정렬된 순서로 넣으면 치우쳐 O(n)까지 간다. 그래서 라이브러리는 회전으로 높이를 묶는 균형 트리를 쓴다.
  • 힙의 구조와 삽입·삭제 — 부모가 자식보다 작은 완전 이진 트리다. 삽입은 끝에 넣고 위로 올리고, 삭제는 루트를 빼고 마지막 원소를 올려 내려 둘 다 O(log N)이다. 빈칸이 없어 배열로 저장하고 자식이 2i+1, 2i+2다.
  • 힙과 이진 탐색 트리의 차이 — 힙은 최솟값만 빠르게 주는 부분 순서 구조다. 이진 탐색 트리는 전체 순서를 유지해 정렬 순회와 범위 질의가 된다.

이런 오해를 한다

  • 힙은 정렬된 구조다 — 부모-자식 관계만 지킨다. 배열을 그대로 출력해도 정렬 순서가 아니다.
  • 이진 탐색 트리는 항상 O(log N)이다 — 균형을 맞추는 트리만 그렇다. 균형 로직이 없으면 정렬 입력에 O(n)이 된다.
  • 힙에서 특정 값 찾기도 O(log N)이다 — 최솟값 경로만 보장되어 임의 탐색은 O(N)이다.
  • 완전 이진 트리는 모든 레벨이 꽉 찬 트리다 — 그건 포화 이진 트리다. 완전 이진 트리는 마지막 레벨만 왼쪽부터 채워지면 된다.
  • 정렬이 필요하면 무조건 SortedDictionary — 삽입이 드물고 순회가 많으면 배열 기반 SortedList가 메모리와 캐시에 낫다.

3줄 정리

  • 트리는 전체 순서, 힙은 최솟값만 지킨다
  • 균형을 안 맞추면 정렬 입력에서 O(n)이 된다
  • 힙은 빈칸이 없어 배열로 쓴다. 자식은 2i+1, 2i+2
