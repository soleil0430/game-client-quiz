Unity 렌더 파이프라인과 셰이더

URP는 C#으로 짠 렌더 파이프라인이다. 확장은 Renderer Feature, 비용은 배리언트로 돌아온다

핵심 개념

Built-in 렌더 파이프라인은 프레임을 그리는 순서가 엔진 내부(C++)에 고정돼 있어, 개발자는 이미지 이펙트나 커맨드 버퍼처럼 정해진 구멍으로만 끼어들 수 있었다. SRP(Scriptable Render Pipeline)는 그 순서를 C#으로 짜게 연 틀이고, URP와 HDRP는 유니티가 SRP 위에 만들어 둔 구현이다. URP는 모바일부터 PC까지, HDRP는 고사양 PC·콘솔용이다.

그래서 Built-in용 조명 셰이더는 URP에서 그대로 돌지 않는 경우가 많다. 표준 셰이더를 쓰던 머티리얼은 URP의 자동 변환 도구가 바꿔 주지만, 직접 쓴 셰이더는 사람이 다시 쓴다. Shader Graph는 URP와 HDRP 양쪽에서 쓸 수 있다.

Renderer Feature는 URP 렌더러의 정해진 시점(예: 불투명을 그린 뒤)에 패스를 하나 더 끼워 넣는 확장점이다. 외곽선 그리기, 화면을 복사해 왜곡에 쓰기, 특정 레이어 재렌더가 대표적이다.

셰이더 성능에서 자주 걸리는 것이 분기다. GPU는 수십 개 스레드를 한 묶음(워프·웨이브)으로 묶어 같은 명령을 실행하므로, 묶음 안에서 조건이 갈리면 양쪽을 모두 실행하고 결과만 골라 쓴다. 머티리얼 상수처럼 묶음 전체가 같은 값으로 갈리는 분기는 싸다. 키워드로 배리언트를 나누면 분기가 사라지는 대신 배리언트 수가 문제가 된다.

#pragma multi_compile _ _MAIN_LIGHT_SHADOWS  // 항상 컴파일, 런타임 토글
#pragma shader_feature_local _EMISSION       // 안 쓰면 빌드에서 빠짐

half4 frag(Varyings i) : SV_Target
{
    half4 c = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, i.uv);
    #ifdef _EMISSION
        c.rgb += _EmissionColor.rgb;
    #endif
    return c;
}

키워드 조합마다 셰이더가 따로 컴파일되므로 키워드가 늘면 조합이 곱으로 폭발한다. 빌드 시간과 용량이 커지고, 처음 쓰는 배리언트를 GPU에 올리는 순간 프레임이 튄다. 안 쓰는 조합이 빠지도록 shader_feature를 쓰고, 빌드 스트리핑으로 잘라 내고, 나머지는 Shader Variant Collection으로 로딩 중에 미리 워밍업한다.

컴퓨트 셰이더는 렌더링 파이프라인 밖에서 GPU 병렬 연산을 쓰는 프로그램이라, 서로 독립적인 데이터 수만 건에 같은 계산을 하는 입자 시뮬레이션·컬링·이미지 처리에 맞는다. 결과를 CPU로 되읽으면 동기화 대기가 생긴다. 파티클 시스템(CPU 갱신, 스크립트·물리 연동)과 VFX Graph(컴퓨트 셰이더로 GPU 갱신)를 나눠 쓰는 것도 같은 이유다.

면접에서 이렇게 답한다

  • Built-in, URP, HDRP 중 무엇을 고르나 — 모바일이 타깃이면 URP다. 다만 Built-in용 커스텀 셰이더는 다시 써야 하는 경우가 많아 전환 비용을 일정에 잡는다.
  • Renderer Feature는 언제 쓰나 — 불투명을 그린 뒤 외곽선을 얹는 식으로 정해진 시점에 패스를 더 넣을 때 쓴다. 커스텀 SRP는 유지 비용이 커서 구조 자체를 갈아야 할 때만 고려한다.
  • 셰이더 분기가 느린 이유 — GPU는 워프 단위로 같은 명령을 실행해서, 워프 안에서 조건이 갈리면 양쪽을 다 돌고 결과만 고른다.
  • 배리언트가 많아지면 — 빌드 시간과 용량이 늘고 처음 쓰는 배리언트를 올릴 때 히칭이 생긴다. shader_feature와 스트리핑으로 줄이고 남는 건 미리 워밍업한다.
  • 컴퓨트 셰이더는 언제 쓰나 — 수만 건의 독립적인 데이터에 같은 계산을 반복할 때 쓴다. 결과를 GPU 안에서 소비해야 이득이 남는다.

흔한 오해

  • URP로 바꾸면 셰이더는 그대로 돈다 — 인클루드 파일과 패스 태그가 달라 Built-in용 조명 셰이더는 대개 재작성이 필요하다.
  • 셰이더 분기도 CPU의 if처럼 한쪽만 실행된다 — 워프 안에서 갈리면 양쪽을 다 돈다.
  • 배리언트는 GPU만 느려지게 한다 — 실제 문제는 빌드 시간, 용량, 첫 사용 시점의 히칭이다.
  • VFX Graph가 파티클 시스템의 상위 호환이다 — CPU 쪽 상호작용이 제한적이고 컴퓨트 셰이더 지원 기기가 필요하다. 게임플레이에 얽힌 효과는 파티클 시스템이 낫다.
  • 포스트 프로세싱은 공짜에 가깝다 — 화면 픽셀 수에 비례하는 패스이고, 모바일에서는 타일 메모리를 비웠다 채우는 비용까지 붙는다.
