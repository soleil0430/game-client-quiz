그래픽스·렌더링

컬링과 가시성

안 그리는 것이 가장 싸다. 시야 밖·가려짐·뒷면·먼 픽셀은 거르는 자리가 다르다

벽 하나를 사이에 두고 방 저편에 소품 200개가 놓여 있다. 화면에는 한 조각도 안 나온다. 이 200개는 그려질까?

아무 설정도 안 해 두면 그려진다. 보이지 않는 것에 쓰는 프레임이 제일 아깝다. 파이프라인 곳곳에 거르는 관문이 놓인 이유다.

관문 네 개는 거르는 단위가 다르다

네 관문을 한 덩어리로 외우면 면접에서 섞인다. 앞의 둘은 CPU가 오브젝트를 목록에서 빼는 일이고, 뒤의 둘은 GPU가 삼각형과 픽셀을 버리는 일이다.

단위가 다르니 할 수 있는 일도 다르다. 백페이스 컬링은 오브젝트를 통째로 없애 주지 못한다. 프러스텀 컬링은 한 메시 안의 안 보이는 면을 골라내지 못한다.

프러스텀 컬링은 오브젝트 단위라 큰 메시에 약하다

프러스텀 컬링은 Unity가 알아서 한다. 오브젝트의 경계 상자가 절두체 여섯 평면 밖이면 목록에서 뺀다.

문제는 그 판정 단위가 오브젝트라는 데 있다.

지형 전체가 메시 하나면 귀퉁이만 화면에 걸쳐도 지형이 통째로 그려진다. 거대한 단일 메시를 쪼개야 컬링이 먹는 이유가 이것이다. 같은 판정을 직접 해 볼 수도 있다:

readonly Plane[] _planes = new Plane[6];  // 매 프레임 새 배열을 만들지 않는다

bool IsInFrustum(Camera cam, Renderer target)
{
    // 카메라 절두체의 여섯 평면을 기존 배열에 채운다
    GeometryUtility.CalculateFrustumPlanes(cam, _planes);
    // 판정은 삼각형이 아니라 렌더러의 경계 상자(bounds) 단위다
    return GeometryUtility.TestPlanesAABB(_planes, target.bounds);
}

void OnBecameInvisible() { enabled = false; }  // 보일 때만 도는 로직은 끈다
void OnBecameVisible()   { enabled = true; }

오클루전 컬링과 LOD는 무엇을 내주고 사나

오클루전 컬링은 벽 뒤처럼 가려진 오브젝트를 뺀다. Unity 기본 방식은 씬을 미리 구워 가시성 데이터를 만들고 런타임에 조회한다. 조회 비용과 구운 데이터를 내고 드로우 콜을 사는 거래라, 막힌 실내에서는 남고 가릴 것 없는 개활지에서는 비용만 남는다.

LOD는 화면에서 차지하는 비율에 따라 폴리곤이 적은 메시로 갈아 끼운다(LODGroup). 정점과 셰이딩 비용이 줄어든다. 대신 단계별 메시를 다 들고 있어야 해서 메모리와 빌드 용량은 늘고, 전환 순간 형태가 튀는 팝핑이 보인다.

백페이스 컬링만 공짜에 가깝다. 화면에 투영된 세 정점이 감기는 방향으로 앞뒤를 가르고, Unity는 시계 방향을 앞면으로 보며 기본값이 Cull Back이다. 정점 순서가 뒤집힌 메시가 안쪽만 보이는 것이 이 때문이고, 나뭇잎처럼 양면이 필요하면 Cull Off로 끈다.

깊이 버퍼가 그리는 순서를 대신 맞춰 준다

깊이 버퍼는 픽셀마다 현재 깊이를 적어 둔다. 더 가까운 조각만 통과시키니 그리는 순서가 어떻든 앞뒤가 맞는다.

함정은 정밀도다. 값이 비선형으로 저장돼 근평면 쪽에 몰린다. near를 너무 작게 잡거나 far를 과하게 키우면 먼 곳에서 Z-파이팅이 난다.

모바일의 타일 기반 GPU는 깊이를 타일 메모리에 두어 이 테스트가 싸다. 가려질 픽셀의 셰이딩을 아예 건너뛰는 하드웨어 기능(PowerVR의 HSR, Adreno의 LRZ)까지 있다.

데스크톱에서 쓰던 깊이 프리패스가 모바일에서 손해가 되기 쉬운 것도 이 때문이다. 하드웨어가 이미 하는 일을 지오메트리 두 번 처리하는 값만 치르고 다시 하는 셈이다. 대신 CPU 예산이 빠듯하니 오브젝트 수를 줄이는 컬링과 LOD는 더 중요해진다.

면접에서 이렇게 답한다

  • 프러스텀 컬링과 오클루전 컬링의 차이 — 둘 다 CPU에서 그릴 목록을 줄인다고 먼저 묶는다. 그다음 프러스텀은 시야 밖을, 오클루전은 시야 안이지만 가려진 것을 뺀다고 가른다. 프러스텀은 자동이고 오클루전은 베이크와 조회 비용이 들어 씬 구조를 보고 켠다.
  • 백페이스 컬링의 판정 기준 — 화면에 투영된 정점이 감기는 방향으로 앞뒤를 가르고 뒷면을 버린다. 메시 노멀이나 정점 순서가 뒤집히면 판정도 뒤집혀 안쪽만 보인다고 증상까지 말한다.
  • LOD의 장단점 — 거리에 따라 단순한 메시로 바꿔 정점과 셰이딩을 아낀다. 대신 단계별 메시만큼 메모리와 용량이 늘고 전환 순간 팝핑이 생긴다.
  • 깊이 버퍼의 동작 — 픽셀마다 깊이를 저장해 더 가까운 조각만 남기므로 순서와 무관하게 앞뒤가 맞는다. 정밀도가 근평면에 몰려 near와 far 비율이 나쁘면 Z-파이팅이 난다는 점을 덧붙인다.

이런 오해를 한다

  • “오클루전 컬링은 켜기만 하면 이득이다” — 베이크 데이터와 조회 비용이 있다. 가릴 것이 없는 개활지에서는 낸 값만 남는다.
  • “백페이스 컬링이 뒤에 있는 오브젝트를 거른다” — 거르는 것은 삼각형의 뒷면이다. 가려진 오브젝트는 오클루전 컬링, 가려진 픽셀은 깊이 테스트가 맡는다.
  • “프러스텀 컬링은 삼각형 단위다” — 오브젝트의 경계 볼륨 단위다. 지형 같은 단일 메시에는 거의 듣지 않는다.
  • “LOD는 메모리도 줄여 준다” — 단계마다 메시를 따로 들고 있다. 메모리와 빌드 용량은 오히려 는다.

3줄 정리

  • 앞의 두 관문은 CPU가 오브젝트 목록을 줄이는 일
  • 뒤의 두 관문은 GPU가 삼각형과 픽셀을 버리는 일
  • 큰 단일 메시는 쪼개야 프러스텀 컬링이 먹는다
