동기화 기법

입력을 맞출지 상태를 맞출지가 갈림길이다. 장르가 답을 정해 준다

내 화면과 상대 화면 사이에는 늘 왕복 시간만큼의 과거가 끼어 있다. 아무리 빨라도 이 차이는 없앨 수 없다. 동기화 기법은 그 차이를 감추는 방법들이다.

입력을 맞출 것인가, 상태를 맞출 것인가

대응은 크게 둘로 갈린다. 입력만 주고받아 각자 같은 시뮬레이션을 돌리거나, 권위 있는 상태를 받아 빈틈을 예측으로 메운다. 어느 쪽이 맞는지는 장르가 정해 준다.

기법보내는 것맞는 장르왜 맞나 / 대가
락스텝입력·명령RTS, 유닛 많은 전략트래픽이 유닛 수와 무관 / 결정론 필요
롤백입력 + 예측격투, 2~4인 대전입력 지연이 없다 / 재시뮬레이션 비용
클라이언트 예측입력과 권위 상태FPS, 액션 MMO서버가 판정 / 빗나가면 위치가 튄다
데드 레커닝·보간위치·속도원격 오브젝트, 레이싱빈도를 낮춰도 된다 / 급선회에 약하다

락스텝은 결정론을, 롤백은 되감기를 산다

락스텝은 입력만 보내고 모두가 같은 시뮬레이션을 돌린다. 유닛 수백 개의 위치를 보내지 않아도 되니 RTS에 맞는다. 대신 모든 기기의 결과가 한 비트도 달라선 안 된다.

그래서 고정소수점을 쓰고 난수 시드와 순회 순서를 고정한다. 한 번 갈라지면 복구가 어려워 상태 체크섬을 주기적으로 비교한다. 진행 속도는 가장 느린 참가자에 묶인다.

롤백은 그 대기를 없앤 락스텝이다. 상대 입력을 예측해 진행하다 실제 입력이 다르면 그 프레임으로 되감아 다시 돌린다. 상태 저장과 재시뮬레이션이 싸야 해서 참가자가 적은 격투에 맞는다.

서버 권한을 지키면서 즉시 반응하게 만드는 법

입력에 번호를 붙여 보내면서 동시에 내 화면에 먼저 적용한다. 서버 상태가 오면 그 시점 위치로 되돌린다. 그리고 서버가 아직 보지 못한 입력만 다시 적용한다.

서버가 확인한 입력을 버리고 나머지만 다시 밟는 부분이다:

public void Push(Vector3 move)                  // 보내면서 먼저 내 화면에 적용
{
    _pending.Add(new Cmd { Seq = ++_seq, Move = move });
    transform.position += move;
}

public void OnServerState(Vector3 pos, uint ackSeq)
{
    _pending.RemoveAll(c => c.Seq <= ackSeq);   // 서버가 처리한 입력은 버린다
    foreach (var c in _pending) pos += c.Move;  // 못 본 입력만 다시 적용
    transform.position = pos;                   // 판정 권한은 서버에 남는다
}

남의 캐릭터는 추정으로 그린다

데드 레커닝은 받은 위치와 속도로 다음 위치를 추정한다. 그렇게 패킷과 패킷 사이를 메운다. 새 값이 오면 순간이동 대신 짧은 시간에 수렴시킨다.

손실을 전제하므로 상태는 델타보다 최신 값을 통째로 보낸다. 보간은 받은 값 사이를 채우느라 한 틱만큼 과거를 보여 준다. 내 캐릭터의 반응성은 예측이 맡는다.

면접에서 이렇게 답한다

  • 데드 레커닝이란 — 받은 위치와 속도로 원격 오브젝트의 다음 위치를 추정해 갱신 사이를 메우는 기법이다. 전송 빈도를 낮춰도 화면이 끊기지 않는다.
  • 락스텝은 어떤 장르에 맞나 — 입력만 주고받아 각자 같은 시뮬레이션을 돌리므로 유닛이 많은 RTS에 맞는다. 결과가 같아야 해서 고정소수점과 시드 고정이 필요하다.
  • 클라이언트 예측과 서버 보정 — 입력에 번호를 붙여 보내고 즉시 로컬에 적용한다. 서버 상태가 오면 그 시점에 맞추고 남은 입력만 다시 적용하며, 판정은 서버가 한다.
  • 롤백 지연 보상 — 상대 입력을 예측해 진행하고 다르면 되감아 재시뮬레이션한다. 입력 지연이 없어 격투에 쓰지만 스냅숏 저장 비용이 든다.

이런 오해를 한다

  • 데드 레커닝은 서버가 과거로 되감는 것이다 — 되감기는 히트스캔 슈터의 서버 측 지연 보상이다. 데드 레커닝은 받은 값으로 앞을 추정하는 것이다.
  • 클라이언트 예측은 판정을 맡기는 것이다 — 미리 그려 볼 뿐이다. 판정은 서버가 하고 결과가 다르면 클라이언트가 맞춰진다.
  • 보간만 켜면 지연이 해결된다 — 보간은 한 틱만큼 과거를 보여 준다. 내 캐릭터는 예측으로 메워야 한다.

3줄 정리

  • 입력을 맞추면 락스텝, 상태를 맞추면 예측
  • 예측은 되돌린 뒤 못 본 입력만 다시 밟는다
  • 남의 캐릭터는 추정과 보간으로 그린다
