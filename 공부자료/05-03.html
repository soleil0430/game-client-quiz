게임 수학·물리

회전

오일러 각은 축이 겹쳐 자유도를 잃는다. 쿼터니언은 축과 반각을 네 숫자에 담는다

인스펙터의 회전은 칸이 셋인데 코드의 rotation에는 w가 있다. 이 차이를 모르면 각도를 더하다 캐릭터가 뒤집힌다. 특정 각도에서 축 하나가 통째로 사라지기도 한다.

오일러 각은 축을 순서대로 쌓는 표현이다

오일러 각은 정해진 순서로 축을 차례차례 돌린 각도 셋이다. 읽고 쓰기 쉽고 값이 셋뿐이라 데이터가 작다. 대신 순서에 기댄다.

Quaternion.Euler는 Z, X, Y 순으로 적용한다. 순서가 다르면 같은 숫자라도 다른 방향을 가리킨다.

각도끼리 직선 보간을 하면 경로가 뒤틀린다. 359도에서 1도로 갈 때는 뒤로 한 바퀴 돈다.

가운데 축이 90도가 되면 자유도 하나가 사라진다

짐벌 락은 축이 겹쳐서 생긴다. 가운데 축이 90도에 이르면 남은 두 축이 같은 방향을 향한다. 서로 다른 축의 회전이 같은 결과를 낸다.

회전 자유도 셋 중 하나를 잃는 셈이다. 그 방향으로 돌릴 수단이 아예 없어진다.

쿼터니언은 축과 반각을 네 숫자에 담는다

쿼터니언은 값 네 개로 어느 축을 얼마나 도는지를 한 번에 담는다. 단위 축 n을 중심으로 각 θ만큼 도는 회전은 x, y, z가 n * sin(θ/2), w가 cos(θ/2)다.

Y축 90도를 넣어 본다. sin(45도)와 cos(45도)가 모두 약 0.7071이다. 그래서 (0, 0.7071, 0, 0.7071)이 된다.

반각이 들어가는 이유는 적용 방식에 있다. 회전을 적용할 때 쿼터니언을 앞뒤로 두 번 곱해 각이 두 배가 된다. 축과 각을 한 덩어리로 다루므로 축이 겹치는 상황이 없다.

길이가 1인 단위 쿼터니언만 회전을 뜻한다. q와 −q는 같은 회전이다. 그래서 Slerp는 최단 경로를 고를 때 부호를 맞춰 본다.

입력은 오일러, 저장은 쿼터니언, 적용은 행렬

회전 행렬은 값이 아홉 개라 저장이 크다. 곱을 반복하면 오차가 쌓여 직교성이 깨진다. 대신 정점에 바로 곱할 수 있다.

표현값 개수특이점쓰는 자리
오일러 각3짐벌 락인스펙터와 기획 데이터
쿼터니언4없음누적과 보간
회전 행렬9오차 누적정점에 적용

만들고, 합치고, 따라 돌리는 세 가지를 코드로 보면 이렇다:

// 축과 각으로 만든다. (x, y, z) = 축 * sin(θ/2), w = cos(θ/2)
Quaternion q = Quaternion.AngleAxis(90f, Vector3.up); // (0, .7071, 0, .7071)

// 오일러로 만들어도 내부는 쿼터니언이다. 적용 순서는 Z -> X -> Y
transform.rotation = Quaternion.Euler(0f, 90f, 0f);

// 합성은 곱이고 오른쪽이 먼저 적용된다. 순서를 바꾸면 결과가 다르다
transform.rotation = q * transform.rotation;

// 목표를 바라보는 회전으로 초당 180도씩 따라 돈다
Quaternion look = Quaternion.LookRotation(target.position - transform.position);
transform.rotation = Quaternion.RotateTowards(transform.rotation, look,
                                              180f * Time.deltaTime);

면접에서 이렇게 답한다

  • 오일러 각 대신 쿼터니언을 쓰는 이유는 — 오일러 각은 축을 순서대로 쌓아 특정 각도에서 자유도를 잃는다. 각도끼리 보간하면 경로도 뒤틀린다. 쿼터니언은 축과 각을 네 성분에 담아 그런 특이점이 없다.
  • 짐벌 락이란 — 가운데 축이 90도가 되면 남은 두 축이 같은 방향을 향하는 현상이다. 서로 다른 축의 회전이 같은 결과를 낸다. 회전 자유도 하나가 사라진다.
  • 인스펙터는 x, y, z인데 rotation에는 왜 w가 있나 — 인스펙터가 보여 주는 것은 사람이 읽기 쉬운 오일러 각이다. rotation은 내부 표현인 쿼터니언이다. 축에 sin(θ/2)를 곱한 셋과 cos(θ/2)인 w까지 있어야 축과 각을 함께 담는다.
  • 방향을 무엇으로 저장하겠나 — 기획자가 만지는 데이터는 오일러 각으로 노출한다. 코드에서 누적하고 보간하는 값은 쿼터니언으로 들고 있는다. 정점에 적용하는 마지막 단계에서만 행렬로 바꾼다.

이런 오해를 한다

  • 쿼터니언을 쓰면 짐벌 락이 사라진다 — 짐벌 락은 오일러 각 표현의 성질이라 그 표현을 안 쓰는 것뿐이다. 중간에 eulerAngles로 읽어 고쳐 넣으면 문제가 돌아온다.
  • rotation.x에 각도를 넣으면 된다 — rotation의 x는 축에 sin(θ/2)를 곱한 값이지 각도가 아니다. 각도를 넣으면 길이가 1이 아니게 되어 회전이 망가진다.
  • eulerAngles를 더하면 안전하게 누적된다 — eulerAngles는 쿼터니언에서 역산한 값이라 −90을 넣고 읽으면 270이 나온다. 누적은 쿼터니언 곱이나 Transform.Rotate로 한다.
  • 회전 곱은 순서를 바꿔도 된다 — 행렬과 마찬가지로 교환법칙이 없다. yaw * pitch와 pitch * yaw는 다른 방향을 만든다.

3줄 정리

  • 오일러 각은 가운데 축 90도에서 자유도 하나를 잃는다.
  • 쿼터니언은 축에 sin(θ/2)를 곱한 셋과 cos(θ/2)를 담는다.
  • 입력은 오일러, 누적과 보간은 쿼터니언, 적용은 행렬이다.
