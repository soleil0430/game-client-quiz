회전

오일러 각은 읽기 쉽지만 짐벌 락이 있고, 쿼터니언은 축과 반각으로 회전을 담는다

핵심 개념

3차원 회전을 저장하는 방법은 오일러 각, 회전 행렬, 쿼터니언 셋이고, 저장 크기, 합성 비용, 보간 품질, 특이점 유무에서 갈린다. 면접에서 묻는 것은 결국 "왜 내부는 쿼터니언인데 인스펙터는 오일러 각인가"다.

오일러 각은 정해진 순서로 축을 차례차례 돌린 각도 셋이다. 읽고 쓰기 쉽고 값이 셋뿐이라 데이터가 작다. 문제는 순서 의존이다. Unity의 Quaternion.Euler는 Z, X, Y 순으로 적용하는데 순서가 다르면 같은 숫자라도 다른 방향을 가리킨다. 더 큰 문제가 짐벌 락이다. 가운데 축이 90도에 이르면 남은 두 축이 같은 방향을 향하게 되어, 서로 다른 축의 회전이 같은 결과를 내고 특정 방향으로 돌릴 수단이 사라진다. 회전 자유도 셋 중 하나를 잃는 것이다. 각도끼리 직선 보간을 하면 경로가 뒤틀리고, 359도에서 1도로 갈 때 뒤로 한 바퀴 돈다.

쿼터니언은 값 네 개로 "어느 축을 중심으로 얼마나 도는가"를 한 번에 담는다. 단위 축 n을 중심으로 각 θ만큼 도는 회전은 x, y, z가 n * sin(θ/2), w가 cos(θ/2)다. Y축 90도면 sin(45도)와 cos(45도)가 모두 약 0.7071이라 (0, 0.7071, 0, 0.7071)이 된다. 반각이 들어가는 이유는 회전을 적용할 때 쿼터니언을 앞뒤로 두 번 곱하는 구조라 각이 두 배가 되기 때문이다. 인스펙터 회전값은 셋인데 rotation에 w가 있는 것이 이 표현이고, 축과 각을 한 덩어리로 다루므로 축이 겹치는 상황이 없어 짐벌 락이 생기지 않는다. 길이가 1인 단위 쿼터니언만 회전을 뜻하고 q와 -q는 같은 회전이라, Slerp는 최단 경로를 고를 때 부호를 맞춰 본다.

회전 행렬은 값이 아홉 개라 저장이 크고 곱을 반복하면 오차가 쌓여 직교성이 깨지지만, 정점에 바로 곱할 수 있다. 그래서 실무의 선택은 이렇게 갈린다. 사람이 입력하고 읽는 자리는 오일러 각, 누적하고 보간하는 내부 저장은 쿼터니언, 정점에 적용하는 마지막 단계는 행렬이다.

void Aim(Transform target)
{
    // 축과 각으로 만든다. (x, y, z) = 축 * sin(θ/2), w = cos(θ/2)
    Quaternion q = Quaternion.AngleAxis(90f, Vector3.up); // (0, 0.7071, 0, 0.7071)

    // 오일러 각으로 만들어도 내부는 쿼터니언이다. 적용 순서는 Z → X → Y
    transform.rotation = Quaternion.Euler(0f, 90f, 0f);

    // 합성은 곱이고 오른쪽이 먼저 적용된다. 순서를 바꾸면 결과가 다르다
    transform.rotation = q * transform.rotation;

    // 목표를 바라보는 회전을 만들어 초당 180도 속도로 따라 돌린다
    Quaternion look = Quaternion.LookRotation(target.position - transform.position, Vector3.up);
    transform.rotation = Quaternion.RotateTowards(transform.rotation, look, 180f * Time.deltaTime);
}

면접에서 이렇게 답한다

  • 오일러 각 대신 쿼터니언을 쓰는 이유는 — 오일러 각은 축을 순서대로 쌓는 표현이라 특정 각도에서 축이 겹쳐 자유도를 잃고, 각도끼리 보간하면 경로가 뒤틀린다. 쿼터니언은 축과 각을 네 성분에 담아 그런 특이점이 없고 Slerp로 최단 경로 보간이 된다.
  • 짐벌 락이란 — 오일러 각으로 순서대로 돌릴 때 가운데 축이 90도가 되면 남은 두 축이 같은 방향을 향해, 서로 다른 축의 회전이 같은 결과를 내는 현상이다. 회전 자유도 하나가 사라진다.
  • 인스펙터는 x, y, z인데 rotation에는 왜 w가 있나 — 인스펙터가 보여주는 것은 사람이 읽기 쉬운 오일러 각이고 rotation은 내부 표현인 쿼터니언이다. 축에 sin(θ/2)를 곱한 셋과 cos(θ/2)인 w까지 있어야 축과 각을 함께 담는다.
  • 방향을 무엇으로 저장하겠나 — 기획자가 만지는 데이터는 오일러 각으로 노출하고, 코드에서 누적하고 보간하는 값은 쿼터니언으로 들고 있는다. 정점에 적용하는 마지막 단계에서만 행렬로 바꾼다.

흔한 오해

  • 쿼터니언을 쓰면 짐벌 락이 사라진다 — 짐벌 락은 오일러 각 표현의 성질이라 그 표현을 안 쓰는 것뿐이다. 중간에 eulerAngles로 읽어 고쳐 다시 넣으면 문제가 돌아온다.
  • rotation.x에 각도를 넣으면 된다 — rotation의 x는 축에 sin(θ/2)를 곱한 값이지 각도가 아니다. 각도를 넣으면 길이가 1이 아니게 되어 회전이 망가진다.
  • eulerAngles를 더하면 안전하게 회전이 누적된다 — eulerAngles는 쿼터니언에서 역산한 값이라 -90을 넣고 읽으면 270이 나오는 식이다. 누적은 쿼터니언 곱이나 Transform.Rotate로 한다.
  • 회전 곱은 순서를 바꿔도 된다 — 행렬과 마찬가지로 교환법칙이 없어 yaw * pitch와 pitch * yaw는 다른 방향을 만든다.
