Unity 엔진

물리

충돌 이벤트가 오느냐는 Rigidbody가 있느냐에서 갈리고, 비용은 콜라이더 모양에서 갈린다

아이템 위를 밟아도 아무 일이 없고, 적은 벽을 뚫고 지나간다. 물리에서 처음 막히는 곳이 여기다. 원인은 대개 Rigidbody가 어디에 붙어 있느냐다.

Rigidbody 없는 콜라이더는 겹쳐도 조용하다

물리 엔진은 모든 콜라이더를 매 틱 서로 비교하지 않는다. Rigidbody가 없는 콜라이더는 영영 움직이지 않는다고 보고 정적 구조에 미리 구워 둔다. 그래서 그런 콜라이더끼리는 겹쳐도 이벤트가 오지 않는다.

Collider는 모양이고, Rigidbody는 그 모양이 시뮬레이션에 참여한다는 표시다. 조합별로 어떤 이벤트가 오는지는 아래와 같다.

조합OnCollisionEnterOnTriggerEnter
Collider ↔ Collider (Rigidbody 없음)없음없음
Rigidbody ↔ Collider발생발생
Kinematic Rigidbody ↔ Collider없음발생
Rigidbody ↔ Rigidbody발생발생
Kinematic ↔ Kinematic없음발생

정적 콜라이더를 옮기면 정적이라 믿고 만든 구조를 다시 만들어야 해 비싸다. 움직일 물체에는 Is Kinematic Rigidbody를 붙여 엔진이 이동을 알게 한다.

Trigger와 Collision은 밀어내느냐에서 갈린다

Is Trigger를 켜면 서로 통과한다. 들어옴과 나감만 알려주므로 획득 범위나 인식 범위에 쓴다.

꺼져 있으면 엔진이 겹침을 풀며 반발력을 계산한다. 그 결과로 접촉점, 상대 속도, 충격량이 Collision 객체에 담겨 온다. 트리거는 밀어낼 게 없으니 이 정보도 없다.

콜라이더 모양은 판정 공식이 단순한 순서대로 싸다. Sphere와 Capsule, Box 다음이 Convex Mesh다. 볼록하지 않은 MeshCollider는 서로 충돌시킬 수 없어 지형 전용이다.

Translate, AddForce, MovePosition 중 무엇을 쓰나

transform.Translate는 물리를 건너뛰고 좌표만 바꿔 벽을 통과한다. AddForce는 힘을 줘 가속을 만들므로 질량이 클수록 덜 움직인다. MovePosition은 다음 틱에 갈 곳을 알려주는 이동이라 충돌 검사가 유지된다.

그래서 조작감을 직접 잡는 캐릭터는 MovePosition이 기본이다. 다음은 입력 읽기와 이동을 나눠 둔 코드다:

// 입력은 Update에서 읽는다. FixedUpdate에서 읽으면 짧게 누른 키를 놓친다
void Update() => input = new Vector3(Input.GetAxisRaw("Horizontal"), 0f,
                                     Input.GetAxisRaw("Vertical"));

void FixedUpdate()   // 이동은 물리 틱에 맞춘다 (rb는 Is Kinematic)
{
    // MovePosition은 "다음 틱에 여기로 간다"라서 충돌 검사와 보간이 유지된다
    rb.MovePosition(rb.position + input.normalized * (speed * Time.fixedDeltaTime));
}

레이는 굵기가 없어 좁은 틈을 통과한다

Raycast는 굵기가 없는 선이다. 얇은 물체나 좁은 틈을 그냥 지나쳐 접지 판정이 뚫린다. SphereCast는 반지름을 가진 구를 쓸어 보내 그 굵기 안의 충돌을 잡는다.

대신 SphereCast가 더 비싸다. 비용을 줄이는 가장 값싼 수단은 Layer Collision Matrix라, 레이어 쌍의 체크를 끄면 그 조합은 검사에서 통째로 빠진다.

Physic Material은 성능이 아니라 마찰과 반발, 즉 촉감을 정하는 에셋이다. 질량은 여기가 아니라 Rigidbody의 Mass에서 정한다.

면접에서 이렇게 답한다

  • 두 오브젝트가 충돌하려면 — 양쪽에 Collider가 있고 적어도 한쪽에 Rigidbody가 있어야 합니다. Rigidbody 없는 콜라이더끼리는 정적으로 취급돼 이벤트가 오지 않습니다.
  • Trigger와 Collision의 차이는 — 트리거는 통과시키며 들어옴과 나감만 알려줍니다. 충돌은 밀어낸 뒤 접촉점과 충격량까지 넘겨줍니다.
  • Kinematic Rigidbody와 Static Collider는 — 둘 다 힘에 반응하지 않습니다. 다만 정적 콜라이더를 옮기면 정적이라 가정하고 만든 구조를 재구축해야 해서 비쌉니다.
  • 물리 기반 캐릭터 이동을 만든다면 — Kinematic Rigidbody에 캡슐 콜라이더를 둡니다. 입력은 Update에서 모아 FixedUpdate에서 MovePosition으로 옮기고, 접지와 벽 판정은 SphereCast로 합니다.

이런 오해를 한다

  • 트리거끼리는 Rigidbody 없이도 이벤트가 온다 — 오지 않는다. 트리거 콜라이더만 붙은 두 오브젝트를 겹쳐도 조용하다. 한쪽에 Kinematic Rigidbody라도 붙여야 한다.
  • MeshCollider가 정확하니 그냥 쓰면 된다 — Convex를 켜야 다른 Rigidbody와 충돌하고, 그마저 볼록 껍질로 근사한다. 움직이는 물체는 기본 도형 몇 개를 조합한다.
  • FixedUpdate가 Update보다 자주 불린다 — 기본 0.02초, 초당 50번이다. 60fps면 Update가 더 자주 돈다.
  • Translate로 옮겨도 충돌은 잡힌다 — 물리를 건너뛴 순간 이동이라 벽 안으로 들어간다. 빠른 물체면 그대로 통과한다.

3줄 정리

  • 한쪽에 Rigidbody가 없으면 충돌 이벤트가 오지 않는다
  • 트리거는 통과시키고, 충돌은 밀어내며 충격량까지 준다
  • 좁은 틈이 걱정이면 Raycast 대신 SphereCast를 쓴다
