Lerp는 비율을 줄 뿐이다. 등속·감쇠·이징 중 무엇이 필요한지 정하고 고른다

핵심 개념

Lerp(a, b, t)는 a + (b - a) * t로 두 값 사이의 중간값을 줄 뿐이고, Unity는 t를 0~1로 잘라 준다(자르지 않으려면 LerpUnclamped).

그 실수는 pos = Vector3.Lerp(pos, target, 0.1f);를 매 프레임 호출하는 코드다. 시작점 a에 현재 값을 다시 넣기 때문에 남은 거리의 10%씩 줄어드는 지수 감쇠가 된다. 남은 비율이 0.9의 프레임 수 제곱이라 1초 뒤 30fps에서는 약 4.2%가 남는데 60fps에서는 0.18%만 남는다. 기기마다 속도가 달라 보이고 목표에 정확히 도착하지도 않는다.

무엇으로 바꿀지는 원하는 움직임에 달렸다. 등속으로 가야 하면 MoveTowards다. 정규화한 방향으로 속도 × Time.deltaTime만큼 나아가되 남은 거리를 넘지 않게 잘라 준다. 감속이면 비율을 상수로 두지 말고 1 - Mathf.Exp(-k * Time.deltaTime)으로 계산해 프레임 독립으로 만든다. 반감기를 0.25초로 잡으면 k는 ln2 / 0.25 = 약 2.77이고, 30fps든 60fps든 0.25초 뒤 남은 거리가 절반이 된다. 속도의 연속성이 필요한 카메라 추적에는 SmoothDamp가 낫다.

Lerp와 Slerp의 차이는 무엇을 일정하게 나누느냐다. Lerp는 직선으로 이어 성분을 비례 배분하고, Slerp는 두 벡터가 이루는 각을 고르게 나눠 구면 위의 호를 따라간다. 방향과 회전은 Slerp가 각속도와 길이를 유지해 자연스럽고, 위치나 색에는 더 싼 Lerp를 쓴다.

이징은 값을 건드리는 것이 아니라 진행도 t 자체를 곡선으로 바꾸는 것이다. 0에서 1로 가는 t를 다른 모양으로 바꿔 넣으면 결과에 가감속이 생긴다. Unity에서는 Mathf.SmoothStep, AnimationCurve, SmoothDamp가 여기 해당하고, UI 연출은 ease-out이 잘 맞는다.

public class Follower : MonoBehaviour
{
    public Transform target;
    public float speed = 5f;        // 초속
    public float stopDistance = 1f; // 이 거리에서 멈춘다
    public float halfLife = 0.25f;  // 남은 거리가 절반이 되는 시간

    // 등속으로 다가가다 거리 1.0에서 멈춘다.
    // MoveTowards가 남은 거리를 넘지 않게 잘라 줘 경계에서 떨지 않는다
    void Update()
    {
        Vector3 to = target.position - transform.position;
        Vector3 goal = target.position - to.normalized * stopDistance;
        transform.position = Vector3.MoveTowards(transform.position, goal, speed * Time.deltaTime);
    }

    // 감속하며 붙는 추적. 비율이 상수가 아니라 프레임레이트와 무관하다
    public Vector3 Damp(Vector3 cur, Vector3 goal, float dt)
        => Vector3.Lerp(cur, goal, 1f - Mathf.Exp(-Mathf.Log(2f) / halfLife * dt));
}

면접에서 이렇게 답한다

  • Lerp와 Slerp의 차이는 — Lerp는 직선으로 이어 비례 배분하고, Slerp는 각을 고르게 나눠 호를 따라간다. 방향과 회전은 Slerp가 각속도를 유지해 자연스럽고, 위치나 색은 Lerp면 충분하다.
  • 매 프레임 Lerp(현재, 목표, t)의 문제는 — 시작점에 현재 값을 다시 넣어 지수 감쇠가 되고, 프레임이 많을수록 빨리 붙어 기기마다 속도가 달라진다. 등속이면 MoveTowards, 감속이면 1 - Exp(-k * deltaTime)이다.
  • 이징이란 — 진행도를 곡선으로 바꿔 가감속을 주는 기법이다. 값이 아니라 t를 바꾼다는 것이 핵심이고 Mathf.SmoothStep과 AnimationCurve가 그 예다.
  • 등속으로 가다 거리 1에서 멈추게 하라 — 정규화한 방향으로 속도 × deltaTime만큼 나아가되, 한 프레임 이동량이 남은 거리를 넘으면 떨리므로 MoveTowards로 잘라 준다.

흔한 오해

  • Lerp를 매 프레임 부르면 등속으로 간다 — 지수적으로 느려지고, 1초 뒤 30fps는 4.2%, 60fps는 0.18%가 남는다.
  • t에 Time.deltaTime을 넣으면 프레임 독립이 된다 — t는 시간이 아니라 비율이라 그대로 넣어도 프레임 수에 따라 달라진다.
  • Slerp가 항상 더 부드럽다 — 위치 보간에는 과하고 비싸며, 두 벡터가 거의 같거나 정반대면 회전축이 불안정해진다.
  • 이징은 결과값에 곡선을 곱하는 것이다 — 곡선을 씌우는 대상은 t다. 값에 곱하면 도착점이 달라진다.
