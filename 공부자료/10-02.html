메모리와 포인터

GC가 없으니 소유권을 코드에 적는다. RAII와 unique_ptr이 그 문법이다

C#에서는 이 객체를 누가 책임지는지 코드에 적을 일이 거의 없다. 가비지 컬렉션(GC)이 걷어 가기 때문이다. C++에는 그 담당자가 없어 소유권과 수명을 코드로 적는다.

C#의 using을 C++은 스코프가 대신한다

자원을 생성자에서 얻고 소멸자에서 놓는 방식이 RAII다. 그러면 자원의 수명이 객체의 수명에 묶인다. 스택 객체는 스코프를 벗어날 때 반드시 소멸자가 불린다.

예외가 나거나 일찍 return해도 해제가 빠지지 않는다. C#의 IDisposable과 using이 같은 목적이지만 using은 부르는 쪽이 적어야 한다. 메모리뿐 아니라 파일 핸들과 락에도 그대로 쓴다.

중간에 빠져나가도 텍스처가 닫히는 형태다:

void Load() {
    auto tex = std::make_unique<Texture>("hero.png");  // 생성자에서 연다
    if (!tex->IsValid())
        return;          // 여기서 나가도
    Use(*tex);
}                        // 스코프를 벗어나면 소멸자가 닫는다

소유자가 몇 명인가로 스마트 포인터를 고른다

스마트 포인터는 RAII를 포인터에 적용한 것이다. 셋 중 무엇을 쓸지는 기준 하나로 정해진다. 이 자원의 소유자가 몇 명인가다.

종류소유쓰는 자리
unique_ptr혼자기본 선택. 복사가 막혀 있고 move로 넘긴다
shared_ptr여럿(참조 카운트)수명을 정말 나눠 가질 때만
weak_ptr없음(관찰만)카운트를 올리지 않는 참조, lock으로 확인

new와 malloc의 차이도 여기서 나온다. new는 타입에서 크기를 계산하고 생성자까지 부르며 실패하면 예외를 던진다. malloc은 바이트만 주고 실패하면 NULL을 돌려준다.

그래서 new로 잡고 free로 놓으면 소멸자 호출과 해제 방식이 어긋난다. 결과는 정의되지 않은 동작이다. new[]를 delete로 놓는 것도 같다.

참조 카운트는 순환을 못 푼다

shared_ptr끼리 서로를 가리키면 카운트가 1 아래로 내려가지 않는다. 둘 다 영영 해제되지 않는다. C#에서는 겪지 않는 누수다.

GC는 루트에서 닿을 수 있는지를 보므로 서로만 가리키는 섬도 수거한다. 참조 카운트에는 그런 시야가 없다. 부모가 자식을 shared_ptr로, 자식이 부모를 weak_ptr로 갖는 식으로 고리를 끊는다.

예외 대신 조용히 망가지는 것들

참조는 선언할 때 대상을 정하고 바꿀 수 없어 항상 유효한 객체를 가리킨다. 포인터는 nullptr일 수 있고 주소를 바꿀 수 있다. 값이 없을 수 있으면 포인터, 반드시 있으면 참조로 받아 의도를 드러낸다.

포인터 멤버가 있는 클래스를 기본 복사 생성자로 복사하면 얕은 복사다. 두 객체가 같은 메모리를 가리켜 이중 해제가 난다. 깊은 복사를 직접 쓰거나 소유권이 분명한 타입으로 바꾼다.

배열은 범위를 검사하지 않는다. 넘어가면 예외가 아니라 정의되지 않은 동작이고, 남의 메모리를 덮어써 한참 뒤 엉뚱한 곳에서 터진다. 구조체 크기도 정렬 때문에 멤버 합보다 커지므로 선언 순서가 크기를 바꾼다.

면접에서 이렇게 답한다

  • RAII란 — 자원의 수명을 객체의 수명에 묶는 기법이다. 생성자에서 얻고 소멸자에서 놓으면 예외나 조기 반환에도 새지 않는다. C#의 using 문과 목적이 같다.
  • 스마트 포인터는 어떻게 고르나 — 소유자가 하나면 unique_ptr을 기본으로 쓴다. 수명을 정말 나눠 가질 때만 shared_ptr을 쓰고, 역방향 참조는 weak_ptr로 둔다.
  • malloc과 new의 차이는 — new는 크기 계산과 생성자 호출까지 하고 실패하면 예외를 던진다. malloc은 할당만 하고 NULL을 주며, 섞어 쓰면 정의되지 않은 동작이 된다.
  • 얕은 복사와 깊은 복사는 — 얕은 복사는 포인터 값만 복사해 이중 해제가 생긴다. 깊은 복사는 새 메모리를 잡아 내용을 옮기며, 요즘은 소유권이 분명한 타입으로 문제 자체를 없앤다.

이런 오해를 한다

  • shared_ptr을 쓰면 누수가 없다 — 서로 가리키는 순환이 생기면 그대로 샌다. GC와 달리 참조 카운트는 순환을 못 푼다.
  • 배열 범위를 넘으면 예외가 난다 — C#의 예외를 떠올린 오해다. 검사가 필요하면 vector의 at을 쓰고 디버깅에는 AddressSanitizer를 쓴다.
  • 참조도 nullptr일 수 있다 — 참조는 초기화 없이 만들 수 없다. 없을 수 있는 값은 포인터로 표현한다.
  • delete와 free는 이름만 다르다 — delete는 소멸자를 부르고 free는 부르지 않는다. 짝을 맞추지 않으면 정의되지 않은 동작이다.

3줄 정리

  • RAII는 자원 수명을 스코프에 묶는다
  • 소유자 수로 unique·shared·weak를 고른다
  • 참조 카운트는 순환 참조를 풀지 못한다
