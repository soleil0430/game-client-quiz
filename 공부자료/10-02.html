메모리와 포인터

GC가 없는 대신 소유권을 코드로 적는다. RAII와 스마트 포인터가 그 문법이다

핵심 개념

C#에서는 GC가 메모리를 걷어 가므로 이 객체를 누가 책임지는지 코드에 적을 일이 거의 없다. C++에는 그 담당자가 없어 소유권과 수명을 코드로 표현한다. 그 방식이 RAII다. 자원을 생성자에서 얻고 소멸자에서 놓으면 자원의 수명이 객체의 수명에 묶인다. 스택 객체는 스코프를 벗어날 때 반드시 소멸자가 불리므로 예외가 나거나 일찍 return해도 해제가 빠지지 않는다. C#의 IDisposable과 using이 같은 목적이지만 using은 적어야 하고, C++은 스코프가 알아서 한다. 메모리뿐 아니라 파일 핸들과 락에도 그대로 쓴다.

void Load() {
    auto tex = std::make_unique<Texture>("hero.png");  // 생성자에서 열고
    if (!tex->IsValid())
        return;                                          // 여기서 나가도
    Use(*tex);
}                                                        // 소멸자에서 닫는다

new와 malloc의 차이도 여기서 나온다. new는 타입에서 크기를 계산해 할당하고 생성자까지 부르며 실패하면 std::bad_alloc 예외를 던진다. malloc은 바이트 수만큼 메모리를 줄 뿐 생성자를 모르고 실패하면 NULL을 돌려준다. 그래서 new로 잡고 free로 놓거나 new[]를 delete로 놓으면 소멸자 호출과 해제 방식이 어긋나 정의되지 않은 동작이 된다.

스마트 포인터는 RAII를 포인터에 적용한 것이다. 셋 중 무엇을 쓸지는 소유자가 몇 명인가로 정한다.

종류소유쓰는 자리
unique_ptr혼자기본 선택. 복사가 막혀 있고 std::move로 소유권을 넘긴다
shared_ptr여럿(참조 카운트)수명을 진짜로 나눠 가질 때. 카운트가 0이 되면 해제한다
weak_ptr없음(관찰만)카운트를 올리지 않는 참조. lock()으로 살아 있는지 보고 쓴다

shared_ptr끼리 서로를 가리키면 카운트가 1 아래로 내려가지 않아 둘 다 영영 해제되지 않는다. 참조 카운트는 순환을 스스로 풀지 못한다. C#의 GC는 루트에서 닿을 수 있는지를 보므로 서로만 가리키는 섬도 수거하지만 shared_ptr은 그렇지 않다. 부모가 자식을 shared_ptr로, 자식이 부모를 weak_ptr로 갖는 식으로 한쪽 고리를 끊는다.

기초 문법도 C#과 대비하면 정리된다. 참조는 선언할 때 대상을 정하고 바꿀 수 없어 늘 유효한 객체를 가리킨다고 보고 쓰며, 포인터는 nullptr일 수 있고 다른 주소로 바꿀 수 있으며 산술 연산도 된다. 값이 없을 수 있으면 포인터, 반드시 있으면 참조로 받아 의도를 드러낸다. 포인터 멤버가 있는 클래스를 컴파일러가 만든 복사 생성자로 복사하면 얕은 복사라 두 객체가 같은 메모리를 가리켜 이중 해제가 난다. 새 메모리를 잡아 내용을 옮기는 깊은 복사를 직접 쓰거나 소유권이 분명한 스마트 포인터로 바꾼다. 배열은 범위를 검사하지 않아 넘어가면 예외가 아니라 정의되지 않은 동작이고, 남의 메모리를 조용히 덮어써 한참 뒤 엉뚱한 곳에서 터지는 쪽이 더 흔하다.

구조체 크기는 정렬 때문에 멤버 크기의 합보다 클 수 있다. struct A { char c; int i; char d; };는 int가 4바이트 경계에 놓여야 해 c 뒤에 3바이트가 들어가고, 전체가 4의 배수가 되도록 d 뒤에 3바이트가 더 붙어 12바이트다. int i; char c; char d; 순서면 8바이트다.

면접에서 이렇게 답한다

  • RAII란 — 자원의 수명을 객체의 수명에 묶는 기법이다. 생성자에서 얻고 소멸자에서 놓으면 스코프를 벗어날 때 반드시 해제되므로 예외나 조기 반환에도 새지 않는다. unique_ptr과 lock_guard가 그 예이고 C#의 using 문과 목적이 같다.
  • 스마트 포인터는 어떻게 고르나 — 소유자가 하나면 unique_ptr을 기본으로 쓰고, 수명을 여러 곳이 정말 나눠 가져야 할 때만 shared_ptr을 쓴다. 고리가 생길 수 있는 역방향 참조는 weak_ptr로 두고 쓸 때 lock()으로 확인한다.
  • malloc과 new의 차이는 — new는 크기 계산과 생성자 호출까지 하고 실패하면 예외를 던지며, malloc은 할당만 하고 실패하면 NULL을 준다. 섞어 쓰면 소멸자가 빠지거나 해제 방식이 어긋나 정의되지 않은 동작이 된다.
  • 얕은 복사와 깊은 복사는 — 얕은 복사는 포인터 값만 복사해 두 객체가 같은 메모리를 공유하므로 이중 해제와 의도치 않은 공유가 생긴다. 깊은 복사는 새 메모리를 잡아 내용을 옮긴다. 요즘은 소유권이 분명한 타입으로 설계해 문제 자체를 없앤다.

흔한 오해

  • shared_ptr을 쓰면 누수가 없다 — 서로 가리키는 순환이 생기면 카운트가 0이 되지 않아 그대로 샌다. GC와 달리 참조 카운트는 순환을 못 푼다.
  • 배열 범위를 넘으면 예외가 난다 — C#의 IndexOutOfRangeException을 떠올린 오해다. 검사가 필요하면 vector::at()이 예외를 던지고, 디버깅에는 AddressSanitizer를 쓴다.
  • 참조도 nullptr일 수 있다 — 참조는 초기화 없이 만들 수 없고 대상을 바꿀 수도 없다. 없을 수 있는 값은 포인터로 표현한다.
  • delete와 free는 이름만 다르다 — delete는 소멸자를 부르고 free는 부르지 않는다. 짝을 맞추지 않으면 정의되지 않은 동작이다.
  • 구조체 크기는 멤버 크기의 합이다 — 정렬 때문에 패딩이 들어가므로 선언 순서가 크기를 바꾼다.
