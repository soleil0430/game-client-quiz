게임 수학·물리

벡터

각도와 앞뒤는 내적, 좌우와 법선은 외적으로 얻는다. 거리는 제곱끼리 비교한다

적이 내 시야에 들어왔는지, 목표가 왼쪽인지, 튕긴 총알이 어디로 갈지. 이걸 조건문으로 하나씩 풀면 끝이 없다.

벡터 연산 두 개면 셋 다 나온다.

내적은 사잇각을 숫자 하나로 바꾼다

내적은 두 길이의 곱에 사잇각의 코사인을 곱한 값이다. 두 벡터가 모두 정규화돼 있으면 내적이 곧 코사인이다. 값 하나를 읽으면 각도를 읽은 셈이 된다.

부호와 크기가 곧 방향이다. 1이면 정면, 0이면 정확히 옆, 음수면 뒤쪽. 0.5면 60도고 0.707이면 45도다.

시야각 판정에 역코사인까지 불러야 할까? 부를 일이 없다. 코사인은 0도에서 180도까지 줄어들기만 하니, 내적을 cos(시야각 절반)과 바로 비교해도 결과가 같다. 계산은 훨씬 싸게 끝난다.

시야각 90도면 기준값이 약 0.707, 120도면 정확히 0.5다.

내적을 한 번 빼면 미끄러짐, 두 번이면 반사

내적에는 두 번째 얼굴이 있다. 투영이다. 단위 법선 N에 대해 Dot(v, N) * N이 v의 법선 방향 성분이고, 이 성분을 얼마나 빼느냐로 결과가 갈린다.

아래에서 I는 들어오는 방향, P는 점, Q는 평면 위의 아무 점이다.

필요한 것식
벽을 따라 미끄러지기I − Dot(I, N) * N
반사I − 2 * Dot(I, N) * N
점 P와 평면의 최단 거리Abs(Dot(N, P − Q))

셋 다 N이 단위 길이라는 전제 위에 서 있다. 정규화를 빠뜨리면 결과가 조용히 틀어진다. 평면 거리에서 절댓값을 벗기면 부호가 앞뒤를 알려 준다.

그럼 왼쪽인지 오른쪽인지는 무엇으로 아나

외적이다. 외적은 두 벡터가 만드는 평면에 수직인 벡터를 준다. 방향은 돌아가는 쪽을, 길이는 평행사변형 넓이를 뜻한다. 순서를 바꾸면 부호가 뒤집힌다.

Unity에서 Cross(forward, toTarget).y가 양수면 목표가 오른쪽에 있다. 정면 (0,0,1)과 오른쪽 (1,0,0)의 외적이 (0,1,0)인 것으로 확인된다.

삼각형 법선도 같은 연산에서 나온다. (B − A)와 (C − A)를 외적한 뒤 정규화하면 된다. 길이가 삼각형 넓이의 두 배라 정규화를 건너뛸 수 없다.

정규화를 빠뜨리면 대각선만 41% 빨라진다

입력 h, v로 만든 Vector3(h, 0, v)를 속도에 그대로 곱한 캐릭터는 대각선으로 달릴 때만 빠르다. 그 벡터의 길이가 약 1.41이어서다. 방향만 필요하면 정규화한다.

거리 비교에서는 제곱근을 부를 일이 아예 없다. 제곱근은 값이 커지면 결과도 커져 대소 관계를 바꾸지 않기 때문이다. sqrMagnitude로 비교하고 기준값도 미리 제곱해 둔다.

시야 판정과 좌우 판정을 한자리에 담으면 이렇다:

public bool CanSee(Transform target)   // 사거리와 시야각을 한 번에 본다
{
    Vector3 to = target.position - transform.position;
    if (to.sqrMagnitude > range * range) return false;  // 기준값도 제곱해 비교
    float cos = Vector3.Dot(transform.forward, to.normalized);
    return cos >= Mathf.Cos(viewAngle * 0.5f * Mathf.Deg2Rad); // 90도면 약 0.707
}

// 앞뒤는 내적, 좌우는 외적의 부호로 가른다
bool IsOnRight(Transform target)
    => Vector3.Cross(transform.forward, target.position - transform.position).y > 0f;

면접에서 이렇게 답한다

  • 내적이 무엇이고 어디에 쓰나 — 두 벡터의 사잇각 코사인에 길이를 곱한 값이라고 연다. 정규화된 벡터끼리면 값이 곧 코사인이다. 시야각 판정을 역코사인 없이 cos(시야각 절반)과의 비교로 끝낸다는 데까지 말한다.
  • 외적의 결과는 무엇을 뜻하나 — 두 벡터가 이루는 평면에 수직인 벡터다. 방향은 돌아가는 쪽, 길이는 평행사변형 넓이다. 삼각형 법선과 좌우 판정을 예로 든다.
  • 벡터를 언제 정규화하나 — 방향만 의미가 있고 길이가 섞이면 안 될 때다. 이동 입력을 그냥 쓰면 대각선이 1.41배 빨라진다는 장면을 든다. 반사와 평면 거리 공식도 단위 법선을 전제한다고 덧붙인다.
  • 거리 비교에 왜 sqrMagnitude를 쓰나 — 제곱근은 대소 관계를 바꾸지 않는데 계산은 비싸다. 매 프레임 많은 대상을 훑는 자리에서 그만큼 아낀다. 기준값을 미리 제곱해 둔다는 말을 빼먹지 않는다.

이런 오해를 한다

  • “내적을 보면 좌우도 알 수 있다” — 코사인은 왼쪽 30도와 오른쪽 30도에 같은 값을 준다. 좌우를 가르는 건 외적의 부호다.
  • “외적 결과가 곧 단위 법선” — 길이가 넓이에 비례하니 정규화가 남아 있다. 정점 셋이 거의 일직선이면 길이가 0에 가까워 불안정하다.
  • “반사는 내적을 한 번 빼는 것” — 그건 벽을 따라 미끄러지는 성분이다. 반사는 법선 성분의 부호를 뒤집는 것이라 두 배로 뺀다.
  • “sqrMagnitude는 그냥 빠른 magnitude” — 값 자체가 다르다. 사거리 5와 비교하려면 25와 비교해야 한다.

3줄 정리

  • 내적은 각도와 앞뒤를, 외적은 좌우와 법선을 준다.
  • 반사는 법선 성분을 두 배로 뺀 값이다. N은 단위 길이여야 한다.
  • 거리 비교는 sqrMagnitude로, 기준값도 제곱해 둔다.
