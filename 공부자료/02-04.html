Unity 엔진

스크립팅 백엔드

C#은 IL로 컴파일된다. 그 IL을 실행 중에 번역하면 Mono, 미리 컴파일하면 IL2CPP다

에디터에서 잘 돌던 코드가 iOS 빌드에서만 죽는다. 문자열로 찾던 타입이 없다며 예외가 난다. 에디터와 빌드가 서로 다른 방식으로 C#을 돌리기 때문이다.

C# 소스가 기기에서 도는 두 갈래 길

C# 소스는 그대로 실행되지 않는다. 먼저 IL(중간 언어)로 컴파일된다. 그 IL을 기기에서 어떻게 네이티브 명령으로 바꿀지 정하는 것이 스크립팅 백엔드다.

Mono는 JIT 방식이다. IL을 앱에 담아 두고 실행 중에 필요한 메서드를 그때그때 번역한다. 빌드가 빨라 개발 반복에 좋다.

IL2CPP는 AOT 방식이다. IL을 전부 C++ 소스로 바꾼 뒤 플랫폼 컴파일러로 미리 컴파일한다. 실행 중 코드 생성을 금지하는 iOS에서는 선택이 아니라 필수다.

빌드 시간짧다길다
실행 성능보통대체로 더 빠르다

AOT라서 따라오는 세 가지 제약

미리 컴파일한다는 성질에서 제약이 나온다. IL2CPP 빌드에서만 터지는 버그는 대개 이 셋 중 하나다.

  • 실행 중 코드 생성이 막힌다. System.Reflection.Emit은 쓸 수 없고, 값을 읽는 리플렉션은 그대로 된다.
  • 아무도 참조하지 않아 보이는 타입을 코드 스트리핑이 잘라낸다. 문자열 이름으로만 접근하는 타입은 link.xml이나 [Preserve]로 보존한다.
  • 값 타입 제네릭은 빌드 때 쓰인 조합만 생성된다. 런타임에 새 조합을 만들면 예외가 난다.

쓸 수 있는 C# 문법은 에디터 버전이 정한다

C# 문법 버전도 여기에 묶인다. Unity 2022 LTS는 C# 9와 .NET Standard 2.1 수준이다. 그보다 최신 문법은 컴파일러가 거부한다.

컴파일을 통과해도 대응하는 런타임 API가 없으면 실행 시점에 깨진다. Unity 6부터 지원 범위가 올라가니 팀이 쓰는 에디터 버전부터 확인한다.

도메인 리로드를 끄면 static이 남는다

에디터에서 플레이를 누르면 Unity가 매니지드 도메인을 다시 올린다. static 필드가 초기값으로 돌아가고 이벤트 구독이 끊긴다. 매번 새로 켠 상태가 되지만 프로젝트가 커지면 그만큼 기다린다.

Reload Domain을 끄면 진입이 빨라진다. 대신 static 값과 이벤트 구독이 이전 플레이 상태 그대로 남는다. 두 번째 플레이부터 동작이 달라지는 이유가 이것이다.

static을 직접 되돌려 두면 꺼도 안전하다: 

public static class ScoreBoard
{
    private static int total;

    // 도메인 리로드를 꺼도 플레이를 시작할 때마다 이 함수가 불린다
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]
    private static void ResetStatics() => total = 0;
}

도메인 리로드는 에디터 전용 설정이다. 빌드에는 영향이 없다.

면접에서 이렇게 답한다

  • Mono와 IL2CPP의 차이 — Mono는 IL을 실행 중에 번역하는 JIT이고 IL2CPP는 IL을 C++로 바꿔 미리 컴파일하는 AOT입니다. IL2CPP가 실행은 빠르지만 빌드가 길고, JIT이 금지된 iOS에서는 필수입니다.
  • IL2CPP로 바꾸면 무엇을 조심하나 — 런타임 코드 생성이 막히고 코드 스트리핑이 돕니다. 문자열로만 접근하는 타입은 잘릴 수 있어 link.xml이나 [Preserve]로 보존합니다. 제네릭도 빌드 때 쓰인 조합만 생성됩니다.
  • 도메인 리로드는 왜 신경 쓰나 — 진입 시간을 줄이려고 끄면 static 값과 이벤트 구독이 남아 두 번째 플레이부터 동작이 달라집니다. RuntimeInitializeOnLoadMethod로 static을 직접 초기화해 두면 안전합니다.

이런 오해를 한다

  • IL2CPP가 만든 C++을 읽고 고치면 된다 — 사람이 읽으라고 만든 코드가 아니다. 최적화와 디버깅은 C# 쪽에서 한다.
  • IL2CPP에서는 리플렉션을 아예 못 쓴다 — 값을 읽는 리플렉션은 된다. 막히는 것은 Reflection.Emit 같은 실행 중 코드 생성이다.
  • IL2CPP로 바꾸면 항상 빨라진다 — 스크립트 실행은 대체로 빨라지지만 GPU나 로드가 병목이면 체감 차이가 없다. 빌드 시간은 확실히 늘어난다.
  • 에디터에서 잘 돌면 IL2CPP 빌드도 똑같이 돈다 — 에디터는 Mono라 스트리핑도 AOT 제약도 없다. 리플렉션이 많은 코드는 빌드로 따로 확인한다.

3줄 정리

  • Mono는 실행 중 번역(JIT), IL2CPP는 미리 컴파일(AOT)
  • iOS는 IL2CPP 필수. 빌드는 길고 실행은 대체로 빠르다
  • 스트리핑·제네릭·Reflection.Emit이 IL2CPP의 함정
