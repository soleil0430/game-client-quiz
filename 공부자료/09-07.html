네트워크

보안

클라이언트가 보낸 값은 전부 사용자가 적어 넣은 값이다. 판정은 서버가 한다

클라이언트가 "골드 100을 받았다"고 말하면 서버가 그대로 적어 주는 게임이 있다. 그러면 메모리 수정 도구 하나로 경제가 무너진다. 보안 설계는 이 말을 믿지 않는 데서 시작한다.

신뢰 경계는 기기 바깥에 긋는다

클라이언트 바이너리와 메모리, 세이브 파일, 오가는 패킷은 모두 사용자 기기 안에 있다. 값을 바꾸고 가로채는 것을 막을 방법이 없다. 그래서 그 안의 모든 것은 신뢰 대상에서 뺀다.

서버가 믿을 수 있는 것은 둘뿐이다. 자신이 계산한 값과 자신이 발급한 토큰이다. 나머지는 사용자가 임의로 적어 넣은 값으로 취급한다.

클라이언트는 했다가 아니라 하려 한다만 보낸다

결과를 정하는 계산은 전부 서버가 한다. 피해량, 재화 증감, 드랍, 쿨다운, 이동 가능 여부가 그 대상이다. 이것이 서버 권한 구조다.

"몬스터를 잡았으니 골드 100을 달라"는 보내지 않는다. 대신 "스킬 3을 12번 몬스터에게 썼다"를 보낸다. 골드는 서버가 정해 통보한다.

의도를 받아 서버가 직접 판정하는 코드다. 검사가 어디에 있는지를 본다:

// playerId는 패킷이 아니라 로그인 토큰에서 꺼낸다. 아니면 남의 계정이 조작된다
public int UseSkill(int playerId, int targetId, double serverNow)
{
    Player p = FindPlayer(playerId);
    Monster m = FindMonster(targetId);
    if (p == null || m == null || m.Hp <= 0) return 0;   // 대상이 살아 있는가
    if (serverNow - p.LastUseTime < Cooldown) return 0;  // 시각은 서버 시계로 잰다
    if (Distance(p.Pos, m.Pos) > p.Range) return 0;      // 사거리도 서버가 본다
    int damage = (int)(p.Attack * 1.5f);                 // 피해량도 서버가 계산한다
    m.Hp -= damage; p.LastUseTime = serverNow;
    return damage;
}

의도도 그대로 믿지 않는다

좌표가 맵 안인지, 직전 위치와의 거리가 경과 시간 대비 최대 속도를 넘지 않는지 확인한다. 쿨다운이 지났는지, 그 아이템을 가졌는지, 대상이 살아 있는지도 본다. 기준 시각은 언제나 서버 시계다.

클라이언트가 보낸 시각으로 쿨다운을 재면 그 값을 고쳐 무한 연타가 된다. 다만 지연 보상 탓에 서버도 클라이언트 말을 어느 정도 받아들여야 한다. 그래서 허용 오차 안이면 받고 벗어나면 보정하거나 거절하고 기록을 남긴다.

마지막 방어선은 통계다. 획득량과 승률을 모아 사후에 걸러 낸다. 실시간 검증이 놓친 것을 여기서 잡는다.

TLS가 막는 것과 못 막는 것

TLS는 인증서로 상대가 진짜 그 서버인지 확인한다. 공개키로 대칭키를 합의한 뒤 본문은 값싼 대칭키로 암호화한다. 이렇게 막는 것은 도청과 중간 변조, 서버 위장이다.

반대로 사용자가 조작한 클라이언트는 막지 못한다. 암호가 기기 안에서 풀리기 때문이다. 같은 이유로 앱에 심은 비밀키는 공개된 값으로 봐야 한다.

그래서 신원은 서버가 발급한 수명 짧은 토큰에서 꺼낸다. 요청 본문의 userId로 권한을 판단하지 않는다. 결제도 클라이언트의 성공 통보가 아니라 서버가 스토어에 영수증을 확인한 뒤 지급한다.

면접에서 이렇게 답한다

  • 치트와 패킷 변조를 어떻게 막나 — 클라이언트를 신뢰 대상에서 빼는 것이 먼저다. 판정과 재화 계산은 서버가 하고, 입력은 범위와 쿨다운, 이동 거리, 소유 여부로 검증한다.
  • 클라이언트의 무엇을 믿으면 안 되나 — 보내온 결과값, 시각, 신원, 로컬 저장 데이터 전부다. 신원은 로그인 토큰에서 꺼내고 세이브 파일은 원본이 아니라 캐시로 다룬다.
  • 민감한 데이터의 통신 보안은 — 전 구간을 TLS 1.2 이상으로 암호화하고 버전과 암호 그룹은 OS 기본값에 맡긴다. 인증서 검증을 끄지 않고 토큰 수명을 짧게 둔다.

이런 오해를 한다

  • 통신을 암호화하면 치트가 막힌다 — TLS는 도청과 중간 변조를 막을 뿐이다. 변조된 클라이언트는 정상 연결로 조작된 값을 보낸다.
  • 난독화와 패킷 암호화로 충분하다 — 복호화 키가 클라이언트 안에 있어 시간이 걸릴 뿐 열린다. 분석 비용을 올릴 뿐 서버 판정을 대신하지 못한다.
  • 클라이언트가 검사하니 서버는 안 봐도 된다 — 클라이언트 검사는 사용자 경험용이다. 같은 검사를 서버가 다시 해야 방어가 된다.
  • 쿨다운은 클라이언트가 보낸 시각으로 잰다 — 조작 가능한 값이다. 서버 시계와 서버가 기록한 마지막 사용 시각으로만 판단한다.

3줄 정리

  • 기기 안의 값은 전부 사용자가 쓴 값이다
  • 클라이언트는 의도만 보내고 판정은 서버가 한다
  • TLS는 구간을 지킬 뿐 치트를 막지 않는다
