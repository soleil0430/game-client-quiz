Unity 엔진

애니메이션·카메라·입력

상태 머신이 클립을 고르고, 카메라는 LateUpdate에서 따라가고, 입력은 액션으로 묶는다

캐릭터 하나가 들고 있는 클립이 수십 개다. 무엇을 언제 재생할지 스크립트가 다 정하면 조건문이 끝없이 늘어난다. Animator는 그 판단을 컨트롤러라는 상태 머신으로 옮긴다.

스크립트는 상황만 알려주고 클립은 컨트롤러가 고른다

Animation 컴포넌트는 클립을 이름으로 재생하는 레거시다. 지금 쓰는 Animator(Mecanim)는 상태, 전이, 파라미터, 레이어를 가진 상태 머신을 들고 다닌다.

그래서 스크립트는 animator.SetFloat("Speed", v)처럼 값만 넘긴다. 무슨 클립이 나갈지는 컨트롤러가 정한다. 레이어를 쓰면 상체와 하체를 따로 재생할 수 있다.

휴머노이드 아바타로 구우면 뼈 구조가 다른 캐릭터에도 같은 애니메이션을 쓸 수 있다. 이 재사용을 리타기팅이라 한다.

전이는 상태 사이, 블렌드 트리는 상태 안

둘은 층이 다르다. 전이는 상태와 상태 사이를 시간을 두고 넘어가는 것이다. 블렌드 트리는 한 상태 안에서 파라미터 값에 따라 여러 클립의 가중치를 섞는 것이다.

걷기와 달리기를 Speed로 잇는 것은 블렌드 트리다. 서 있다가 공격으로 넘어가는 것은 전이다. 전이만으로 속도별 이동을 만들면 계단처럼 끊긴다.

IK(역운동학)는 계산 방향이 반대다. 관절 각도를 넣어 손끝 위치를 얻는 대신, 손끝 목표를 주고 관절 각도를 역으로 푼다. 경사면에 발을 맞추거나 손을 무기 손잡이에 붙일 때 쓴다.

IK를 쓰려면 Animator 레이어의 IK Pass를 켜야 OnAnimatorIK가 불린다. 그 안에서 SetIKPosition과 SetIKPositionWeight로 목표와 가중치를 준다.

카메라를 Update에서 옮기면 한 프레임씩 떤다

카메라가 캐릭터를 따라갈 때는 LateUpdate에서 옮긴다. Update에서 옮기면 아직 안 움직인 위치를 따라가 매 프레임 떨린다.

3인칭 카메라를 직접 만들면 추적, 감쇠, 벽 충돌 회피, 시야각 보정을 각각 붙여야 한다. 실무에서는 Cinemachine으로 조합한다.

Cinemachine은 Virtual Camera가 규칙만 들고 있는 구조다. 실제로 그리는 것은 Brain이 붙은 카메라 하나다. Timeline은 애니메이션과 오디오 트랙을 시간축에 배치하는 편집기이고, 컷신 말고 런타임 연출에도 쓴다.

키를 묻는 대신 점프라는 액션을 정의한다

예전 Input Manager는 Input.GetKeyDown(KeyCode.Space)처럼 기기의 키를 직접 물었다. 패드와 터치를 붙이면 분기가 늘고, 키 바꾸기도 코드 일이 된다.

새 Input System은 점프라는 액션을 먼저 정의한다. 키보드 스페이스, 패드 버튼, 터치는 그 액션의 바인딩으로 연결한다. 리바인딩과 플랫폼별 조작이 설정 데이터로 끝난다.

다음은 액션을 구독하고 값을 읽는 코드다:

void OnEnable()
{
    // 키가 아니라 액션을 찾는다. WASD와 패드 스틱이 한 액션에 묶여 있다
    move = actions.FindAction("Move");
    jump = actions.FindAction("Jump");
    jump.performed += OnJump;   // 눌린 순간만 필요하면 콜백
    actions.Enable();
}

// 구독은 반드시 푼다. 안 풀면 파괴된 오브젝트가 계속 불린다
void OnDisable() { jump.performed -= OnJump; actions.Disable(); }

void Update() { Vector2 dir = move.ReadValue<Vector2>(); }   // 값은 폴링

면접에서 이렇게 답한다

  • Animation과 Animator의 차이는 — Animation은 클립을 이름으로 재생하는 레거시입니다. Animator는 상태와 전이, 파라미터, 레이어를 가진 상태 머신으로 클립을 고릅니다.
  • IK는 무엇이고 언제 쓰나 — 목표 지점을 주고 관절 각도를 역으로 푸는 계산입니다. 경사면 발 위치 보정이나 손을 무기에 고정할 때 씁니다.
  • 3인칭 카메라는 어떻게 구현하나 — 추적과 감쇠, 벽 충돌 회피를 나눠 만들고 반드시 LateUpdate에서 옮깁니다. 실무에서는 Cinemachine의 Virtual Camera를 상황별로 전환합니다.
  • 새 Input System은 무엇이 다른가 — 키를 직접 묻는 대신 액션을 정의하고 기기별 바인딩을 따로 겁니다. 그래서 리바인딩과 멀티 플랫폼 대응이 설정 데이터로 끝납니다.

이런 오해를 한다

  • Animator는 Animation의 이름만 바뀐 것 — 재생 방식이 다르다. Animation에는 상태 머신도 파라미터도 리타기팅도 없다.
  • 블렌드 트리와 전이는 같은 것 — 블렌드 트리는 한 상태 안에서 클립을 동시에 섞고, 전이는 상태 사이를 넘어간다.
  • Virtual Camera가 실제 카메라다 — Virtual Camera에는 Camera 컴포넌트가 없다. 규칙만 들고 있고 그리는 것은 Brain이 붙은 카메라 하나다.
  • 새 Input System을 넣으면 Input.GetKey를 못 쓴다 — Active Input Handling을 Both로 두면 둘 다 동작한다. New만 고르면 옛 API가 예외를 던진다.

3줄 정리

  • 스크립트는 파라미터만 넘기고 클립은 컨트롤러가 고른다
  • 전이는 상태 사이, 블렌드 트리는 한 상태 안에서 섞는다
  • 카메라는 LateUpdate, 입력은 키가 아니라 액션 단위
