C++ 기초

현대 C++

값 복사가 기본이라 이동이 필요하다. 템플릿은 타입마다 코드를 찍어낸다

C#에서 대입은 참조 하나를 복사하는 일이다. C++에서 벡터를 값으로 넘기면 원소 전부가 따라 복사된다.

C++11 이후에 들어온 기능 대부분이 이 한 줄 차이에서 나왔다.

복사가 기본이라 이동이 필요했다

곧 사라질 임시 객체까지 통째로 복사하는 것은 낭비다. 그 낭비를 없애려고 나온 것이 이동 의미론이다. 곧 사라질 객체의 자원을 복사하지 않고 넘겨받아 복사를 줄인다.

구분 기준은 값 범주다. 이름이 있어 주소를 얻을 수 있는 식이 l-value이고, 리터럴이나 계산 결과 같은 임시 값이 r-value다. const&는 임시 객체도 묶을 수 있어 읽기만 하는 인자를 받을 때 쓴다.

이동 생성자와 이동 대입 연산자는 rvalue 참조(T&&)를 받아 원본이 가진 자원 포인터를 가져오고 원본은 비워 둔다. 복사가 아니라 소유권 이전이다. 그래서 원소가 열 개든 백만 개든 비용이 같다.

std::move는 아무것도 옮기지 않는다

std::move는 값을 옮기는 함수가 아니라 대상을 rvalue 참조로 캐스팅해 이동 생성자가 선택되게 할 뿐이다. 이동 생성자가 없는 타입에 쓰면 조용히 복사된다. 이동된 원본은 유효하지만 값이 정해지지 않은 상태로 남고, 소멸자는 여전히 호출된다.

같은 줄에서 복사와 이동을 나란히 놓은 예다:

std::vector<int> a = MakeData();      // 임시값이라 이동 또는 복사 생략
std::vector<int> b = a;               // 복사: 원소를 전부 옮겨 담는다
std::vector<int> c = std::move(a);    // 이동: 버퍼 포인터만 가져온다
// a는 유효하지만 내용은 보장되지 않는다. a.clear()로 상태를 정해 준다

함정이 하나 있다. 이름이 붙은 r-value 참조 변수 자체는 l-value다. 다시 이동으로 넘기려면 std::move를 한 번 더 써야 한다.

템플릿은 제네릭과 달리 컴파일 타임에 찍어낸다

C# 제네릭은 하나의 IL로 컴파일되고 런타임이 타입을 다룬다. 템플릿은 쓰인 타입마다 컴파일러가 코드를 따로 찍어낸다. 이것을 인스턴스화라고 부른다.

덕분에 타입 안전하고 실행 중 형변환 비용이 없다. 값은 빌드 쪽에서 치른다. 타입마다 코드가 따로 생성돼 코드가 불어나고 실행 파일이 커질 수 있으며 컴파일이 느려진다. 오류 메시지가 길고 읽기 어려운 것도 단점으로 꼽힌다.

인스턴스화 시점에 정의가 보여야 해서 보통 정의까지 헤더에 둔다.

inline과 const, static은 이름과 실제가 다르다

인라인은 함수 호출 자체를 없애고 본문을 부르는 자리에 펼치는 것이다. 짧은 함수에서는 호출 비용이 사라져 빨라지지만, 본문이 크거나 호출 지점이 많으면 코드가 불어나 명령어 캐시 적중률이 떨어져 오히려 느려질 수 있다.

게다가 inline은 강제가 아니라 권고이고 실제 판단은 컴파일러가 한다. 안 붙여도 인라인하고, 붙여도 안 할 수 있다. 헤더에 정의한 함수를 여러 파일에서 포함해도 중복 정의 오류가 나지 않게 하는 역할이 더 크다.

const 정확성은 C#에 마땅한 짝이 없다. 함수 뒤에 붙는 const는 이 함수가 멤버 변수를 바꾸지 않는다는 선언이라, const 객체나 const&로 받은 객체에서도 부를 수 있다. 지켜 두면 바꾸지 않는 코드가 문서처럼 드러나고 실수를 컴파일러가 잡아 준다.

캐시 값처럼 예외가 필요한 멤버는 mutable로 선언하면 const 함수 안에서도 바꿀 수 있다.

static은 붙는 자리마다 뜻이 달라진다. 전역 변수나 함수에 붙은 static은 내부 연결(internal linkage)을 뜻해 그 파일 안에서만 보이게 제한되고, 다른 파일에서 이름이 부딪히지 않게 한다.

클래스의 정적 멤버는 객체가 아니라 클래스에 하나만 있고 this가 없다. 함수 안 정적 지역 변수는 처음 호출될 때 한 번 초기화돼 프로그램이 끝날 때까지 값을 유지한다. 요즘은 파일 한정 목적이면 익명 네임스페이스를 더 많이 쓴다.

면접에서 이렇게 답한다

  • 이동 의미론은 무엇을 해결하나 — C++은 값 복사가 기본이라 곧 사라질 임시 객체까지 내용을 통째로 복사한다고 배경을 깐다. 이동 생성자는 버퍼 포인터만 가져오므로 원소 수와 무관하게 끝난다고 답한다.
  • std::move는 무엇을 하나 — 옮기는 함수가 아니라 r-value 참조로 바꾸는 캐스트다. 그 덕에 이동 생성자가 선택되고, 원본은 유효하지만 값이 정해지지 않은 상태로 남는다.
  • 템플릿의 장단점은 — 타입마다 코드를 찍어내므로 타입이 안전하고 실행 중 비용이 없다. 대신 실행 파일이 커지고 컴파일이 느려지며 정의를 헤더에 둬야 한다.
  • const를 왜 붙이나 — 바꾸지 않는다는 약속을 타입에 적으면 의도가 드러나고 실수는 컴파일러가 잡는다. const 객체에는 const 멤버 함수만 부를 수 있다.

이런 오해를 한다

  • “std::move가 실제로 데이터를 옮긴다” — 캐스트일 뿐이다. 받는 타입에 이동 생성자가 없으면 그대로 복사가 일어난다.
  • “이동된 객체는 못 쓰고 소멸자도 안 불린다” — 유효하지만 값이 정해지지 않은 상태다. 소멸자는 그대로 불린다.
  • “이름 붙은 r-value 참조 변수는 r-value다” — 이름이 붙는 순간 l-value다. 계속 이동으로 넘기려면 std::move를 다시 쓴다.
  • “템플릿은 런타임에 타입을 다뤄 느리다” — C# 제네릭과 섞은 오해다. 결정은 컴파일 타임에 나고, 값은 빌드 시간과 코드 크기로 치른다.

3줄 정리

  • C++은 값 복사가 기본이라 이동이 필요하다
  • std::move는 캐스트고 이동은 생성자가 한다
  • 템플릿은 타입마다 코드를 찍어낸다
