현대 C++

값 복사가 기본이라 이동이 필요하다. 템플릿은 타입마다 코드를 찍어낸다

C#에서 대입은 참조 하나를 복사하는 일이다. C++에서 벡터를 값으로 넘기면 원소 전부가 복사된다. C++11 이후 기능 대부분이 이 차이에서 나왔다.

C#은 참조를 대입하고 C++은 내용을 복사한다

곧 사라질 임시 객체까지 통째로 복사하는 것은 낭비다. 그래서 나온 것이 이동 의미론이다. 복사 대신 원본이 들고 있던 버퍼를 넘겨받는다.

구분 기준은 값 범주다. 이름이 있어 주소를 얻을 수 있는 식이 l-value다. 리터럴이나 함수가 돌려준 임시값처럼 곧 사라지는 식이 r-value다.

이동 생성자는 r-value 참조를 받아 버퍼 포인터만 가져오고 원본을 비운다. 복사가 아니라 소유권 이전이다. 그래서 원소가 몇 개든 비용이 같다.

std::move는 옮기지 않는다, 캐스트일 뿐이다

std::move는 대상을 r-value 참조로 바꾸는 캐스트다. 실제 이동은 그 결과로 선택된 이동 생성자가 한다. 이동 생성자가 없는 타입에 쓰면 조용히 복사된다.

같은 줄에서 복사와 이동을 비교한 예다:

std::vector<int> a = MakeData();      // 임시값이라 이동 또는 복사 생략
std::vector<int> b = a;               // 복사: 원소를 전부 옮겨 담는다
std::vector<int> c = std::move(a);    // 이동: 버퍼 포인터만 가져온다
// a는 유효하지만 내용은 보장되지 않는다. a.clear()로 상태를 정해 준다

함정이 하나 있다. 이름이 붙은 r-value 참조 변수 자체는 l-value다. 다시 이동으로 넘기려면 std::move를 한 번 더 써야 한다.

템플릿은 제네릭과 달리 컴파일 타임에 찍어낸다

C# 제네릭은 하나의 IL로 컴파일되고 런타임이 타입을 다룬다. 템플릿은 쓰인 타입마다 컴파일러가 코드를 따로 찍어낸다. 이것을 인스턴스화라고 한다.

그래서 타입 안전하고 실행 중 형변환 비용이 없다. 대신 실행 파일이 커지고 컴파일이 느려지며 오류 메시지가 길다. 인스턴스화 시점에 정의가 보여야 해서 정의까지 헤더에 둔다.

inline과 const, static은 이름과 실제가 다르다

inline은 강제가 아니라 권고다. 실제 인라인 여부는 컴파일러가 정하고 inline 없이도 한다. 표준에서 이 키워드의 뜻은 여러 파일에 정의가 있어도 된다는 쪽에 가깝다.

const 정확성은 C#에 대응이 거의 없다. 멤버 함수 뒤의 const는 멤버를 바꾸지 않겠다는 약속이다. 덕분에 const 객체에서도 부를 수 있고 실수는 컴파일러가 잡는다.

static은 붙는 자리마다 뜻이 다르다. 전역에 붙으면 그 파일에서만 보이고, 클래스 멤버면 클래스에 하나만 있다. 함수 안 지역 변수면 처음 호출될 때 한 번 초기화돼 끝까지 값을 유지한다.

면접에서 이렇게 답한다

  • 이동 의미론은 무엇을 해결하나 — C++은 값 복사가 기본이라 곧 사라질 임시 객체까지 내용을 통째로 복사한다. 이동 생성자는 버퍼 포인터만 가져오므로 원소 수와 무관하게 끝난다.
  • std::move는 무엇을 하나 — 옮기는 함수가 아니라 r-value 참조로 바꾸는 캐스트다. 그 덕에 이동 생성자가 선택되고, 원본은 유효하지만 값이 정해지지 않은 상태로 남는다.
  • 템플릿의 장단점은 — 타입마다 코드를 찍어내므로 타입 안전하고 실행 중 비용이 없다. 대신 실행 파일이 커지고 컴파일이 느려지며 정의를 헤더에 둬야 한다.
  • const를 왜 붙이나 — 바꾸지 않는다는 약속을 타입에 적으면 의도가 드러나고 실수는 컴파일러가 잡는다. const 객체에는 const 멤버 함수만 부를 수 있다.

이런 오해를 한다

  • std::move가 실제로 데이터를 옮긴다 — 캐스트일 뿐이다. 이동 생성자가 없는 타입에 쓰면 조용히 복사된다.
  • 이동된 객체는 못 쓰고 소멸자도 안 불린다 — 유효하지만 값이 정해지지 않은 상태다. 소멸자는 그대로 불린다.
  • 이름 붙은 r-value 참조 변수는 r-value다 — 이름이 붙는 순간 l-value다. 계속 이동으로 넘기려면 std::move를 다시 쓴다.
  • 템플릿은 런타임에 타입을 다뤄 느리다 — C# 제네릭과 섞은 오해다. 컴파일 타임에 결정되고 대신 빌드 시간과 코드 크기를 낸다.

3줄 정리

  • C++은 값 복사가 기본이라 이동이 필요하다
  • std::move는 캐스트고 이동은 생성자가 한다
  • 템플릿은 타입마다 코드를 찍어낸다
