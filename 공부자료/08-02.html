메모리 구조

네 구역은 수명이 달라서 나뉜다. 스택은 함수가 끝나면 걷히고 힙은 놓을 때까지 남는다

크래시 로그에 StackOverflow와 OutOfMemory는 다르게 찍힌다. 어느 구역이 터졌는지 모르면 고칠 자리를 못 찾는다. 프로세스 메모리는 수명이 다른 네 구역으로 나뉘어 있다.

네 구역을 가른 기준은 수명이다

코드에는 컴파일된 기계어가, 데이터에는 전역·정적 변수가 들어간다. 힙에는 실행 중에 잡는 동적 할당이 쌓인다. 스택에는 함수 호출마다 지역 변수와 매개변수와 복귀 주소가 쌓인다.

나눠 둔 이유는 사는 기간이 다르기 때문이다. 코드와 전역은 프로그램이 도는 내내 살아 있다. 스택은 함수가 끝나면 사라지고, 힙은 놓아 줄 때까지 남는다.

스택이 빠른 이유는 정리 방식이 단순해서다

스택 할당은 포인터를 올렸다 내리는 것이 전부다. 빈 자리를 찾을 일도, 단편화도 없다. 방금 건드린 영역을 다시 쓰니 CPU 캐시에도 거의 항상 올라와 있다.

힙은 원하는 크기를 원하는 시점에 잡는 자유를 준다. 대신 빈 블록을 찾아야 한다. 잡았다 놓기를 반복하면 빈 공간이 흩어져, 총량은 남는데 큰 덩어리를 못 잡는 상태가 된다.

스택 오버플로와 OutOfMemory는 다른 사고다

스택 오버플로는 스레드마다 고정된 스택 크기를 넘겼다는 뜻이다. 종료 조건 없는 재귀가 대표적이다. 깊은 계층을 재귀로 훑거나 큰 배열을 지역 변수로 잡아도 난다.

에디터에서 멀쩡하다가 실기기에서만 터지는 일이 여기서 나온다. 스레드 스택 크기가 플랫폼마다 다르기 때문이다. 깊이가 커질 수 있으면 반복문과 명시적 스택으로 바꾸는 편이 안전하다.

UI 계층을 훑는 코드를 재귀에서 반복문으로 바꾼 모습:

void Traverse(Transform root)                   // 계층이 깊으면 스택 오버플로
    { foreach (Transform c in root) Traverse(c); }  // 호출마다 프레임이 쌓인다

void TraverseIterative(Transform root)          // 힙에 만든 스택으로 바꾼다
{
    var stack = new Stack<Transform>();        // 이 스택은 힙이라 유연하다
    stack.Push(root);
    while (stack.Count > 0)                     // 호출 프레임은 하나로 유지
    {
        Transform t = stack.Pop();
        foreach (Transform c in t) stack.Push(c);
    }
}

C#에서 구조체가 힙으로 가는 경우

클래스 인스턴스는 관리 힙에 놓여 가비지 컬렉션(GC)이 수거한다. 구조체는 지역 변수일 때만 스택에 놓인다. 클래스의 필드이거나 박싱되면 구조체라도 힙으로 간다.

"구조체는 스택, 클래스는 힙"이라고 외운 문장이 자주 틀리는 지점이다. 어디에 놓이는지는 타입이 아니라 어디에 선언했는지가 정한다.

면접에서 이렇게 답한다

  • 프로세스 메모리 구조를 설명하라 — 코드·데이터·힙·스택 네 구역이고 나눈 기준은 수명과 정리 방식이다. 스택은 함수 반환 때 통째로 걷히고 힙은 해제나 GC가 필요하다. 힙과 스택은 주소 공간의 양끝에서 서로를 향해 자란다.
  • 스택과 힙 중 어느 쪽이 빠른가 — 스택이다. 할당과 해제가 포인터 이동뿐이고 방금 건드린 영역이라 캐시 적중률이 높다. 힙은 빈 블록 탐색과 단편화가 따라오고 C#이면 GC 부담이 붙는다.
  • 스택 오버플로는 언제 나나 — 스레드마다 고정된 스택 크기를 넘길 때다. 무한 재귀가 대표적이고 깊은 계층 순회나 큰 지역 배열도 원인이 된다. 힙 고갈인 OutOfMemory와는 구분해서 말해야 한다.
  • 스택과 힙의 크기는 언제 정해지나 — 스택은 스레드를 만들 때 예약 크기가 정해져 실행 중에 늘지 않는다. 힙은 실행 중에 OS에서 더 받아 오며 늘어난다.

이런 오해를 한다

  • 전역 변수는 힙에 있다 — 전역과 static은 데이터 영역에 잡혀 프로그램이 끝날 때까지 산다. 힙은 실행 중에 요청해 받는 영역이다.
  • C#에서 구조체는 언제나 스택이다 — 클래스의 필드이거나 박싱되면 힙에 함께 놓인다. 타입이 아니라 선언 위치가 정한다.
  • 힙이 부족하면 스택 오버플로가 난다 — 힙 고갈은 OutOfMemoryException이다. 두 영역은 한계가 따로 있다.
  • 스택 크기는 늘리면 그만이다 — 스레드마다 주소 공간을 예약하므로 무작정 키우면 스레드를 많이 못 만든다. 깊은 재귀를 반복문으로 바꾸는 쪽이 낫다.

3줄 정리

  • 코드·데이터·힙·스택을 가른 기준은 수명과 정리 방식이다
  • 스택은 포인터만 움직여 빠르고, 크기는 스레드마다 고정이다
  • 구조체가 클래스 필드이거나 박싱되면 스택이 아니라 힙에 있다
