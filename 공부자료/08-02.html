메모리 구조

코드·데이터·힙·스택이 무엇을 담고 언제 정리되는지 알면 크래시 로그가 읽힌다

핵심 개념

프로세스의 주소 공간은 성격이 다른 네 구역으로 나뉜다. 코드에는 컴파일된 기계어가, 데이터에는 전역·정적 변수가, 힙에는 실행 중에 잡는 동적 할당이, 스택에는 함수 호출마다 쌓이는 지역 변수와 매개변수와 복귀 주소가 들어간다. 나눠 둔 이유는 수명이 다르기 때문이다. 코드와 전역은 프로그램이 도는 내내 살아 있고, 스택은 함수가 끝나면 사라지고, 힙은 놓아 줄 때까지 남는다.

영역무엇이 들어가나언제 정리되나크기가 정해지는 때
코드기계어프로세스 종료빌드 시점
데이터전역·static 변수프로세스 종료빌드 시점
스택지역 변수, 매개변수, 복귀 주소함수 반환 때 자동스레드를 만들 때 고정
힙new·malloc으로 잡은 것해제 또는 GC 수거실행 중 늘었다 줄었다

스택이 빠른 이유는 알고리즘이 좋아서가 아니라 정리 방식이 단순해서다. 스택 포인터를 올렸다 내리는 것이 할당과 해제의 전부라 빈 자리를 찾을 일도, 단편화도 없다. 게다가 방금 건드린 영역을 다시 쓰니 CPU 캐시에 거의 항상 올라와 있다. 힙은 원하는 크기를 원하는 시점에 잡는 자유를 주는 대신 빈 블록을 찾아야 하고, 잡았다 놓기를 반복하면 빈 공간이 흩어져 총량은 남는데 큰 덩어리를 못 잡는 상태가 된다.

스택 오버플로는 그 고정 크기를 넘겼다는 뜻이다. 종료 조건 없는 재귀가 대표적이지만, 깊은 계층을 재귀로 훑거나 큰 배열을 지역 변수로 잡아도 난다. 힙이 모자라는 OutOfMemory와는 아예 다른 사고다. 게임에서는 노드가 많은 UI 계층이나 씬 그래프를 재귀로 순회할 때 에디터에서는 멀쩡하다가 실기기에서만 터지는 일이 있는데, 스레드 스택 크기가 플랫폼마다 다르기 때문이다. 깊이가 커질 수 있으면 반복문과 명시적 스택으로 바꾸는 편이 안전하다.

void Traverse(Transform root)               // 깊으면 스택 오버플로
{
    foreach (Transform c in root) Traverse(c);
}

void TraverseIterative(Transform root)      // 호출 스택 대신 힙의 스택을 쓴다
{
    var stack = new Stack<Transform>();
    stack.Push(root);
    while (stack.Count > 0)
    {
        Transform t = stack.Pop();
        foreach (Transform c in t) stack.Push(c);
    }
}

C#에는 한 겹이 더 붙는다. 클래스 인스턴스는 관리 힙에 놓여 GC가 수거하고, 구조체는 지역 변수일 때만 스택에 놓인다. 클래스의 필드이거나 박싱되면 구조체라도 힙으로 간다. "구조체는 스택, 클래스는 힙"이라고 외운 문장이 자주 틀리는 지점이다.

면접에서 이렇게 답한다

  • 프로세스 메모리 구조를 설명하라 — 코드·데이터·힙·스택 네 구역이고, 나눈 기준은 수명과 정리 방식이다. 스택은 함수 반환 때 통째로 걷히고 힙은 해제나 GC가 필요하다. 힙과 스택은 보통 주소 공간의 양끝에서 서로를 향해 자란다.
  • 스택과 힙 중 어느 쪽 접근이 빠른가 — 스택이다. 할당·해제가 포인터 이동뿐이고 방금 건드린 영역이라 캐시 적중률이 높다. 힙은 빈 블록 탐색과 단편화가 따라오고, C#이면 GC 부담까지 붙는다.
  • 스택 오버플로는 언제 나나 — 스레드마다 고정된 스택 크기를 넘길 때다. 무한 재귀가 대표적이고 깊은 계층 순회나 큰 지역 배열도 원인이 된다. 힙 고갈인 OutOfMemory와는 구분해서 말해야 한다.
  • 스택과 힙의 크기는 언제 정해지나 — 스택은 스레드를 만들 때 예약 크기가 정해져 실행 중에 늘지 않는다. 힙은 실행 중 OS에서 더 받아 오며 늘어난다.

흔한 오해

  • 전역 변수는 힙에 있다 — 전역·static은 데이터 영역에 잡혀 프로그램이 끝날 때까지 산다. 힙은 실행 중에 요청해 받는 영역이다.
  • C#에서 구조체는 언제나 스택이다 — 클래스의 필드이거나 박싱되면 힙에 함께 놓인다. 어디에 놓이는지는 타입이 아니라 어디에 선언됐는지가 정한다.
  • 힙이 부족하면 스택 오버플로가 난다 — 힙 고갈은 OutOfMemoryException이다. 두 영역은 한계가 따로 있다.
  • 스택 크기는 늘리면 그만이다 — 스레드마다 주소 공간을 예약하므로 무작정 키우면 스레드를 많이 만들지 못한다. 깊은 재귀를 반복문으로 바꾸는 쪽이 낫다.
