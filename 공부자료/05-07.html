기초 수학

삼각함수와 근의 공식을 게임 판정에 쓰고, float 오차가 만드는 증상까지 안다

핵심 개념

삼각함수는 각도와 방향을 오가는 환율이다. 단위원에서 각 θ인 점이 (cos θ, sin θ)이므로, 각도로 방향을 만들 때는 sin·cos를, 방향에서 각도를 되찾을 때는 atan2를 쓴다. Unity의 Mathf 삼각함수는 모두 라디안을 받고 돌려주므로, 도 단위와 섞을 때는 Mathf.Deg2Rad와 Mathf.Rad2Deg를 곱한다.

파형 변형은 네 숫자로 끝난다. A·sin(ω·t + φ) + c에서 A는 진폭, ω는 각속도라 주기가 2π/ω, φ는 위상, c는 중심이다. 밖에 곱한 수가 높이를, 안에 곱한 수가 빠르기를 바꾼다. 그래서 Mathf.Sin(Time.time * 2f) * 3f는 −3에서 3까지, 주기 2π/2 = π ≈ 3.14초로 오르내린다.

float phase;   // Time.time 대신 누적하면 시작 시점과 일시정지를 제어할 수 있다

void Update()
{
    phase += Time.deltaTime * speed;
    transform.position = origin + Vector3.up * (Mathf.Sin(phase) * amplitude);
}

atan2가 atan보다 나은 이유는 정보량이다. Mathf.Atan(y / x)는 나누는 순간 두 성분의 부호가 섞여 −π/2~π/2만 돌려주고 (1, 1)과 (−1, −1)을 구분하지 못하며, x가 0이면 나눗셈부터 깨진다. Mathf.Atan2(y, x)는 둘을 따로 받아 사분면을 가려 −π~π 전 범위를 안전하게 돌려준다. 조준 방향, 조이스틱 각도, 미니맵 아이콘 회전이 모두 이 함수다. 두 각의 차이는 ±180도에서 뒤집히므로 Mathf.DeltaAngle로 구한다.

근의 공식은 광선과 구의 교차에서 그대로 나온다. 광선 위의 점을 구 방정식에 넣으면 거리 t에 대한 at² + bt + c = 0이 되고, 판별식 b² − 4ac의 부호가 곧 답이다. 음수면 실근이 없어 비껴가고, 0이면 접하고, 양수면 관통해 교차점이 둘이다. 그래서 판별식으로 대부분을 걸러낸 뒤 필요할 때만 제곱근을 계산한다. 두 근 중 작은 쪽이 앞쪽 교차점이고, 그 값이 음수면 광선 뒤라 버린다.

부동소수점은 이 계산들이 딛고 선 바닥이다. float는 가수가 24비트뿐이라 유효 숫자가 7자리 남짓이고, 0.1처럼 2진수로 딱 떨어지지 않는 수는 근사값으로 저장된다. 0.1을 열 번 더한 값이 1.0과 ==로 같지 않은 이유다. 더 중요한 성질은 값이 클수록 표현 간격이 벌어진다는 것이다.

원점에서의 거리구분되는 최소 간격보이는 증상
1m약 0.0000001m문제 없다
100,000m약 0.008m멈춘 물체가 떨리고 카메라가 지글거린다
1,000,000m약 0.06m위치가 격자에 스냅되고 물리가 흔들린다

증상별 대응은 이렇다. 넓은 월드에서 멀리 간 캐릭터가 떨리면 월드 원점을 주기적으로 옮겨(플로팅 오리진) 좌표를 0 근처로 되돌린다. 몇 시간 켜 둔 게임에서 Time.time으로 돌리던 sin 애니메이션이 끊기는 것도 같은 이유라, 시간을 누적하고 2π마다 되감는다. 크기가 다른 두 수를 빼면 유효 숫자가 날아가 판별식이 0에 가까운 스침 판정에서 결과가 튄다. 길이가 0에 가까운 벡터를 정규화하면 NaN이 나오고, NaN은 퍼지기만 해서 오브젝트가 화면에서 사라진다.

면접에서 이렇게 답한다

  • atan2는 어디에 쓰나 — 방향 벡터를 각도로 바꿀 때 쓴다. y와 x를 따로 받아 사분면을 구분하므로 −π~π 전 범위를 돌려주고 x가 0이어도 안전하다. 캐릭터를 목표 쪽으로 돌릴 때 쓴다.
  • 근의 공식은 어디에 쓰나 — 광선과 구의 교차가 대표적이다. 판별식의 부호로 비껴감·접함·관통을 가르고, 제곱근은 필요할 때만 계산한다고 말한다.
  • sin 그래프를 설명하라 — A·sin(ωt + φ) + c로 쓰고 A가 진폭, 주기가 2π/ω라고 말한다. 둥실 뜨는 아이템과 깜빡이는 UI가 그 예다.
  • float 비교는 어떻게 하나 — == 대신 차이의 절댓값을 허용 오차와 비교한다. 오차는 다루는 값의 크기에 맞춰 정하고, Mathf.Epsilon은 0 근처에서만 의미 있어 기준으로 쓰지 않는다.

흔한 오해

  • Atan(y / x)로 충분하다 — 나누는 순간 부호 정보가 합쳐져 사분면을 잃고 결과가 반 바퀴 틀어진다. x가 0이면 계산 자체가 깨진다.
  • 판별식이 음수면 교차점이 광선 뒤라는 뜻이다 — 실근이 아예 없어 비껴간 것이다. 뒤에 있는 경우는 실근이 있으면서 t가 음수인 경우다.
  • Mathf.Sin은 도(degree)를 받는다 — 라디안이다. 도 값을 그대로 넣으면 입력이 57배 커져 주기가 그만큼 짧아진 것처럼 보인다.
  • double을 쓰면 오차가 사라진다 — 자릿수가 늘어 늦게 드러날 뿐 성질은 같다. Unity의 Transform과 물리 API는 float이라 결국 변환된다.
