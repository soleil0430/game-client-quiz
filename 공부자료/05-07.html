게임 수학·물리

기초 수학

삼각함수와 근의 공식이 판정을 만들고, float 간격이 증상의 원인을 만든다

조이스틱을 기울인 방향으로 캐릭터를 돌리고, 총알이 구에 맞는지 풀고, 원점에서 100km 떨어진 캐릭터가 왜 떠는지 안다.

이 셋이 각각 삼각함수와 근의 공식, 부동소수점이다.

각도와 방향은 sin·cos·atan2로 오간다

삼각함수는 각도와 방향을 오가는 환율이다. 각도를 내밀면 방향을 주고, 방향을 내밀면 각도를 돌려준다. 단위원에서 각 θ인 점이 (cos θ, sin θ)다.

환율과 다른 점이 하나 있다. 가는 길과 오는 길에 쓰는 함수가 다르다.

각도로 방향을 만들 때는 sin과 cos를 쓴다. 방향에서 각도를 되찾을 때가 atan2고, Mathf.Atan(y / x)로는 안 된다.

왜 안 될까? 나누는 순간 두 부호가 하나로 합쳐진다. (1, 1)과 (−1, −1)을 구분하지 못하고, x가 0이면 아예 깨진다.

Mathf.Atan2(y, x)는 둘을 따로 받아 사분면을 가린다. −π에서 π까지 전 범위를 안전하게 돌려준다. 조준 방향, 조이스틱 각도, 미니맵 아이콘 회전이 모두 이 함수다.

Unity의 Mathf 삼각함수는 모두 라디안을 쓴다. 도 단위와 섞을 때는 Mathf.Deg2Rad와 Mathf.Rad2Deg를 곱한다. 두 각의 차이는 ±180도에서 뒤집히므로 Mathf.DeltaAngle로 구한다.

파형 변형은 네 숫자로 끝난다

A·sin(ω·t + φ) + c가 전부다. A는 진폭, ω는 각속도, φ는 위상, c는 중심이고 주기는 2π/ω다.

밖에 곱한 수가 높이를, 안에 곱한 수가 빠르기를 바꾼다. Mathf.Sin(Time.time * 2f) * 3f를 예로 보자. −3에서 3까지 오르내리고 주기는 2π/2 = π ≈ 3.14초다.

둥실 뜨는 아이템과 깜빡이는 UI가 이 식이다.

시작 시점과 일시정지를 제어하려면 Time.time 대신 위상을 누적한다:

float phase;   // Time.time 대신 누적하면 시작 시점을 제어할 수 있다

void Update()
{
    phase += Time.deltaTime * speed;
    if (phase > Mathf.PI * 2f) phase -= Mathf.PI * 2f;   // 2π마다 되감는다
    transform.position = origin + Vector3.up * (Mathf.Sin(phase) * amplitude);
}

판별식 하나로 비껴감·접함·관통이 갈린다

근의 공식은 광선과 구의 교차에서 그대로 나온다. 광선 위의 점을 구 방정식에 넣으면 거리 t에 대한 at² + bt + c = 0이 된다. 판별식 b² − 4ac의 부호가 곧 답이다.

음수면 실근이 없어 비껴간다. 0이면 접한다. 양수면 관통해 교차점이 둘이다.

제곱근은 마지막에 부르면 된다. 판별식으로 대부분을 걸러낸 뒤 필요할 때만 계산한다. 두 근 중 작은 쪽이 앞쪽 교차점이고, 그 값이 음수면 광선 뒤라 버린다.

멀리 간 캐릭터는 왜 떨리나

float가 값이 클수록 간격이 벌어지기 때문이다. 가수가 24비트뿐이라 유효 숫자가 7자리 남짓이고, 0.1처럼 2진수로 딱 떨어지지 않는 수는 근사값으로 저장된다. 0.1을 열 번 더한 값이 1.0과 ==로 같지 않은 이유가 그것이다.

더 중요한 성질은 간격이다.

원점에서의 거리구분되는 최소 간격보이는 증상
1m약 0.0000001m문제 없다
100,000m약 0.008m멈춘 물체가 떨리고 카메라가 지글거린다
1,000,000m약 0.06m위치가 격자에 스냅되고 물리가 흔들린다

넓은 월드에서 멀리 간 캐릭터가 떨면 월드 원점을 주기적으로 옮긴다. 이것이 플로팅 오리진이다. 몇 시간 켜 둔 게임에서 Time.time으로 돌리던 sin이 끊기는 것도 같은 이유다.

크기가 다른 두 수를 빼면 유효 숫자가 날아간다. 판별식이 0에 가까운 스침 판정에서 결과가 튀는 자리가 여기다. 길이가 0에 가까운 벡터를 정규화하면 NaN이 나오고, NaN은 퍼지기만 해 오브젝트가 화면에서 사라진다.

면접에서 이렇게 답한다

  • atan2는 어디에 쓰나 — 방향 벡터를 각도로 바꿀 때 쓴다. y와 x를 따로 받아 사분면을 구분하므로 −π에서 π까지 전 범위를 돌려주고 x가 0이어도 안전하다. 캐릭터를 목표 쪽으로 돌릴 때가 그 자리다.
  • 근의 공식은 어디에 쓰나 — 광선과 구의 교차가 대표적이다. 판별식의 부호로 비껴감과 접함, 관통을 가른다. 제곱근은 필요할 때만 계산한다고 덧붙인다.
  • sin 그래프를 설명하라 — A·sin(ωt + φ) + c로 쓰고 A가 진폭, 주기가 2π/ω라고 말한다. 둥실 뜨는 아이템과 깜빡이는 UI를 예로 든다.
  • float 비교는 어떻게 하나 — == 대신 차이의 절댓값을 허용 오차와 비교한다. 오차는 다루는 값의 크기에 맞춰 정한다. Mathf.Epsilon은 0 근처에서만 의미가 있어 기준으로 쓰지 않는다.

이런 오해를 한다

  • “Atan(y / x)로 충분하다” — 나누는 순간 부호 정보가 합쳐져 사분면을 잃는다. 결과가 반 바퀴 틀어지고 x가 0이면 계산 자체가 깨진다.
  • “판별식이 음수면 교차점이 광선 뒤” — 실근이 아예 없어 비껴간 것이다. 뒤에 있는 경우는 실근이 있으면서 t가 음수인 경우다.
  • “Mathf.Sin은 도(degree)를 받는다” — 라디안이다. 도 값을 그대로 넣으면 입력이 57배 커져 주기가 그만큼 짧아진 것처럼 보인다.
  • “double을 쓰면 오차가 사라진다” — 자릿수가 늘어 늦게 드러날 뿐 성질은 같다. Unity의 Transform과 물리 API는 float이라 결국 변환된다.

3줄 정리

  • 방향에서 각도는 atan2로 얻는다. Atan은 사분면을 잃는다.
  • 파형은 A·sin(ωt + φ) + c, 주기는 2π/ω다.
  • float 간격은 값이 클수록 벌어져 먼 좌표에서 떨림이 된다.
