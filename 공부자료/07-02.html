자료구조·알고리즘

배열과 리스트

연속으로 놓느냐 흩어 놓느냐가 접근 비용과 캐시 적중률을 함께 가른다

인벤토리 목록을 매 프레임 훑는데 프레임이 튄다. 원소 수는 그대로인데 List로 담을 때와 LinkedList로 담을 때가 다르다.

차이는 하나다. 원소를 메모리에 이어 붙였느냐, 흩어 놓고 참조로 이었느냐.

주소를 계산하느냐, 따라가느냐

배열은 같은 크기의 원소를 빈틈없이 이어 붙인다. i번째 주소는 시작 주소 + i × 원소 크기로 바로 나온다. 계산 한 번으로 접근해 끝나니 임의 접근이 O(1)이다.

대신 앞이나 중간에 넣으면 뒤 원소를 전부 한 칸씩 밀어야 해서 O(n)이 된다. 연결 리스트는 정반대다. 노드마다 다음 참조를 들고 흩어져 있어서 i번째까지 처음부터 하나씩 따라가야 한다.

그럼 삽입은 연결 리스트가 빠른가. 조건이 붙는다. 넣을 자리의 노드를 이미 손에 들고 있어야 포인터만 바꿔 O(1)로 넣고 뺀다.

자리를 찾는 비용이 빠진 값이라는 뜻이다. 순회는 둘 다 O(n)으로 같다.

연산 배열 · List<T> 연결 리스트 · LinkedList<T>
인덱스로 접근 O(1) O(n)
맨 뒤에 추가 O(1) 분할 상환 O(1)
앞·중간 삽입 O(n), 뒤 원소 이동 노드를 알면 O(1)
순회 O(n), 캐시에 유리 O(n), 캐시 미스 잦음
원소당 메모리 값만 값 + 참조 2개 + 헤더

복잡도가 같은 순회에서 실측이 갈리는 이유

CPU는 메모리를 캐시 라인 단위로 읽는다. 보통 64바이트를 통째로 당겨 온다. 배열은 원소가 메모리에 붙어 있어 한 번 읽으면 여러 원소가 딸려 오고, 하드웨어 프리페치도 잘 듣는다.

연결 리스트는 노드가 힙에 흩어져 있어 참조를 따라갈 때마다 매번 캐시 미스가 나기 쉽다. 게다가 주소를 읽어야 다음 주소를 아니 미리 당겨 오지도 못한다.

복잡도는 둘 다 O(n)인데 실측은 몇 배씩 갈리는 대표 사례이며, 원소가 연속해 있어 캐시 적중률이 높기 때문이다. 그래서 잦은 중간 삽입이 없다면 대체로 연결 리스트보다 배열 쪽이 낫다.

List<T>는 사실 동적 배열이다

C#의 List<T>는 속에 T[] 하나를 들고 있다. Add로 채우다 용량이 차면 대개 두 배로 늘린 새 배열에 기존 원소를 전부 복사한다. 버려진 옛 배열은 가비지 컬렉션(GC) 대상이 된다.

그 순간은 O(n)이지만 확장이 드물게 일어나므로 Add 한 번의 분할 상환 비용은 O(1)이다. 넣을 개수를 미리 안다면 new List<T>(capacity)로 잡아 두어 복사와 GC 할당을 줄이는 것이 게임 코드에서 흔한 요령이다.

LinkedList<T>는 반대로 원소마다 노드 객체를 하나씩 할당한다. 중간 삽입이 아주 잦고 노드 참조를 이미 들고 있는 경우가 아니면 거의 언제나 List<T>가 낫다.

연결 리스트 뒤집기는 참조 세 개면 된다

단골 문제다. 노드를 새로 만들지 않고 이전·현재·다음 세 포인터로 링크 방향을 하나씩 바꾼다. 시간 O(n), 공간 O(1)로 끝나는 풀이다: 

public static Node Reverse(Node head)
{
    Node prev = null, curr = head;
    while (curr != null)
    {
        Node next = curr.Next;  // 먼저 보관하지 않으면 뒤쪽을 통째로 잃는다
        curr.Next = prev;       // 링크를 반대로 돌린다
        prev = curr;
        curr = next;
    }
    return prev;                // 원래 꼬리가 새 머리다
}

세 변수를 두고 셋을 한 칸씩 전진시키는 일을 끝까지 반복한다. next를 미리 보관하지 않고 링크를 끊으면 뒤쪽 노드를 잃어버리는 것이 이 문제의 단골 실수다.

면접에서 이렇게 답한다

  • 배열과 연결 리스트의 차이 — 배열은 연속 메모리라 인덱스 접근이 O(1)이고 중간 삽입이 O(n)이다. 연결 리스트는 정반대로 접근이 O(n)이고 위치를 알면 삽입이 O(1)이다. 실전에서는 캐시 지역성 때문에 배열이 유리하다는 말까지 붙인다.
  • List와 LinkedList 중 무엇을 썼나 — 거의 List<T>라고 답한다. 순회가 압도적으로 많고 노드 할당이 없어 GC에도 유리하다. LinkedList<T>는 노드 참조를 들고 재배치를 자주 하는 캐시 만료 목록 정도에 쓴다.
  • 동적 배열이 꽉 차면 — 두 배 용량의 새 배열을 잡아 전체를 복사한다. 한 번은 O(n)이지만 나눠 갚으면 Add당 O(1)이다. 개수를 알면 생성자에 용량을 넘겨 확장을 아예 피한다.

이런 오해를 한다

  • “삽입·삭제는 연결 리스트가 빠르다” — 자리를 찾는 O(n)이 빠진 말이다. 인덱스만 아는 상태라면 배열이 더 빠른 경우가 많다.
  • “복잡도가 같으니 순회 속도도 같다” — 캐시 미스 때문에 같은 O(n) 순회가 몇 배씩 차이 난다.
  • “List<T>.Remove는 싸다” — 찾는 데 O(n), 뒤 원소를 당기는 데 또 O(n)이다. 순서가 상관없으면 마지막 원소와 맞바꾼 뒤 끝을 지워 O(1)로 만든다.
  • “Clear()하면 메모리가 준다” — Count만 0이 되고 내부 배열 용량은 그대로 남는다. 풀링에서는 이 성질이 오히려 이득이다.

3줄 정리

  • 배열은 주소를 계산하고, 연결 리스트는 따라간다
  • 같은 O(n) 순회도 캐시 때문에 몇 배 차이 난다
  • 기본은 List<T>, 용량을 미리 잡으면 GC가 준다
