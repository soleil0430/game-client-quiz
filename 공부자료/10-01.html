클래스와 가상 함수

C#과 달리 virtual이 없으면 재정의가 아니다. 그 대가가 vtable이다

C# 습관대로 자식에 같은 이름의 함수를 만들면 재정의가 되지 않는다. 부모 포인터로 부르면 부모 버전이 불린다. C++은 정적 바인딩이 기본이기 때문이다.

virtual이 없으면 재정의가 아니라 가리기다

virtual을 붙이지 않으면 호출 대상이 컴파일 시점에 정해진다. 기준은 실제 객체가 아니라 포인터나 참조의 타입이다. 자식이 같은 이름을 써도 부모 함수를 가릴 뿐이다.

C#에서는 virtual과 override가 짝이지만 new로 가리기도 한다. C++의 기본 동작이 그 new 쪽에 가깝다고 보면 맞는다. override는 C++11부터 있고, 적어 두면 오타를 컴파일러가 잡아 준다.

vtable은 클래스당 하나, 객체에는 포인터 하나

virtual을 붙이면 컴파일러가 클래스마다 함수 주소 표를 하나 만든다. 이것이 vtable이다. 객체에는 그 표를 가리키는 포인터인 vptr이 들어간다.

호출은 vptr에서 표로, 표에서 실제 함수로 한 번 더 건너뛴다. 그래서 부모 포인터로도 실제 객체의 함수가 불린다. 비용은 포인터 하나와 간접 호출, 그리고 인라인이 막힌다는 점이다.

선언과 호출을 한 화면에 놓은 예다. override와 가상 소멸자를 본다:

struct Base {
    virtual ~Base() = default;   // 다형적으로 쓸 기반 클래스의 규칙
    virtual void Update() {}
};
struct Derived : Base {
    void Update() override {}    // override를 적으면 오타를 컴파일러가 잡는다
};

Base* p = new Derived();
p->Update();                     // vptr을 따라가 Derived::Update가 불린다
delete p;                        // 가상 소멸자라 Derived 다음 Base 순으로 소멸

생성 순서와 가상 소멸자가 vtable에서 따라 나온다

생성자는 vptr을 세우는 주체라 virtual일 수 없다. Base 생성자가 도는 동안 vptr은 아직 Base를 가리킨다. 그래서 생성자 안에서 부른 가상 함수는 자식 버전이 불리지 않는다.

생성은 Base, Derived 멤버, Derived 생성자 순이고 소멸은 그 역순이다. 멤버는 초기화 리스트에 적은 순서가 아니라 선언 순서로 초기화된다. C#에서 겪지 않던 함정이 여기 몰려 있다.

가상 소멸자가 필요한 이유도 같다. 부모 포인터로 delete할 때 소멸자가 virtual이 아니면 정의되지 않은 동작이다. 보통 Base 소멸자만 불려 자식이 들고 있던 자원이 샌다.

캐스트 네 개를 C#과 짝지어 둔다

vtable에는 타입 정보도 달려 있어 dynamic_cast와 typeid가 실행 중 실제 타입을 본다. 그래서 부모에 가상 함수가 하나도 없으면 다운캐스트용 dynamic_cast를 쓸 수 없다. 검사 비용도 든다.

면접에서 이렇게 답한다

  • 가상 함수는 어떻게 동작하나 — 클래스마다 함수 주소 표인 vtable이 하나 생기고 객체에는 vptr이 들어간다. 호출할 때 vptr을 따라가므로 부모 포인터로도 자식 구현이 불린다.
  • 가상 소멸자는 왜 필요한가 — 부모 포인터로 delete할 때 virtual이 아니면 정의되지 않은 동작이고 자식 소멸자가 불리지 않는다. 다형적으로 쓸 기반 클래스는 소멸자를 public virtual로 둔다.
  • struct와 class의 차이는 — C++에서는 기본 접근 지정자만 다르다. 스택인지 힙인지는 지역 변수인지 new인지가 정하며, C#의 값 형식 구분과는 다른 이야기다.
  • 생성과 소멸 순서는 — 생성은 부모부터, 소멸은 자식부터다. 부모 생성자가 도는 동안에는 자식이 없어 그 안에서 부른 가상 함수는 부모 버전이 불린다.

이런 오해를 한다

  • vtable은 객체마다 하나씩 들어간다 — 표는 클래스당 하나다. 객체가 갖는 것은 그 표를 가리키는 포인터 하나다.
  • 자식에 같은 이름 함수를 만들면 재정의된다 — 부모에 virtual이 없으면 가리기다. 부모 포인터로는 부모 함수가 불린다.
  • 생성자에서 가상 함수를 부르면 자식 버전이 불린다 — 그 시점에는 자식이 없다. 초기화가 끝난 뒤 따로 부르게 설계한다.
  • C++ struct는 값 형식이라 스택에 잡힌다 — C#과 섞은 오해다. new로 만들면 struct도 힙에 잡힌다.

3줄 정리

  • C++은 virtual을 붙여야 재정의가 된다
  • vtable은 클래스당 하나, 객체엔 포인터 하나
  • 부모 포인터로 지울 거면 소멸자도 virtual
