C++ 기초

클래스와 가상 함수

C#과 달리 virtual이 없으면 재정의가 아니다. 그 대가가 vtable이다

C# 습관대로 자식에 같은 이름의 함수를 만들었다. 부모 포인터로 불렀더니 부모 버전이 돈다.

C++은 정적 바인딩이 기본이라서 그렇다. virtual을 붙이지 않으면 재정의가 아니다.

virtual이 없으면 재정의가 아니라 가리기다

virtual이 아닌 함수는 정적 바인딩이라 컴파일 시점의 포인터 타입으로 호출 대상이 정해진다. 기준은 실제 객체가 아닌 포인터나 참조에 적힌 타입이다. 자식의 같은 이름 함수는 재정의가 아니라 부모 함수를 가리는 것(name hiding)이라 부모 포인터로는 Base::Func가 호출된다.

실제 객체 타입을 따르게 하려면 부모에 virtual을 붙여야 하고, 자식에는 override를 적어 실수를 컴파일러가 잡게 한다.

C#에서 virtual과 override가 짝이라면, 이름만 겹치게 두는 new도 있다. C++의 기본 동작은 그 new 쪽에 가깝다고 보면 맞는다. override는 C++11부터 쓸 수 있고, 적어 두면 오타를 컴파일러가 잡아 준다.

vtable은 클래스당 하나, 객체에는 포인터 하나

컴파일러는 가상 함수가 있는 클래스마다 함수 주소 표(vtable)를 하나 만들고, 각 객체에는 그 표를 가리키는 포인터(vptr)를 넣는다. 표는 클래스당 하나라 객체마다 복사되지 않는다.

호출할 때 vptr에서 vtable로, 표에서 실제 함수 주소를 거치므로 간접 호출 비용이 있고 인라인하기 어렵다. 덕분에 부모 포인터로도 실제 객체의 함수를 찾는다. 같은 이유로 생성자는 virtual로 만들 수 없고, 생성자 안에서 가상 함수를 부르면 파생 클래스 버전이 호출되지 않는다.

선언과 호출을 한 화면에 놓은 예다. override와 가상 소멸자를 본다:

struct Base {
    virtual ~Base() = default;   // 다형적으로 쓸 기반 클래스의 규칙
    virtual void Update() {}
};
struct Derived : Base {
    void Update() override {}    // override를 적으면 오타를 컴파일러가 잡는다
};

Base* p = new Derived();
p->Update();                     // vptr을 따라가 Derived::Update가 불린다
delete p;                        // 가상 소멸자라 Derived 다음 Base 순으로 소멸

생성자 안에서 부른 가상 함수는 왜 자식 걸 못 찾나

생성자는 vptr을 세우는 주체라 자기가 virtual일 수 없다. Base 생성자가 도는 동안 vptr은 아직 Base를 가리킨다. 그 시점에 자식은 만들어지지도 않았다.

생성은 Base 생성자 → Derived의 멤버 초기화 → Derived 생성자 순으로 진행되고, 소멸은 그 역순인 Derived 소멸자 → Base 소멸자 순이다. 초기화 순서는 멤버 선언 순서를 따르므로 초기화 리스트에 적은 순서와 다를 수 있다. C#에서 겪지 않던 함정이 여기 몰려 있다.

가상 소멸자가 필요한 이유도 뿌리가 같다. 부모 포인터로 자식 객체를 delete할 때 소멸자가 virtual이 아니면 동작이 정의되지 않는다. 보통은 Base 소멸자만 불려 Derived가 가진 자원이 새어 나간다.

객체가 복사되는 시점도 C#과 다르다. 복사 생성자는 새 객체를 기존 객체로 초기화할 때 불리는데, 값으로 함수 매개변수에 넘기면 매개변수라는 새 객체를 만드는 것이라 여기서 불린다. 이미 있는 객체에 =로 넣는 것은 복사 대입 연산자 쪽이고, 참조나 포인터로 넘기면 복사가 없으므로 큰 객체는 const&로 받는 것이 관례다.

= 0을 붙이면 객체로 만들 수 없는 클래스가 된다

virtual void F() = 0;처럼 선언한 순수 가상 함수가 하나라도 있으면 그 클래스는 추상 클래스가 되어 인스턴스를 만들 수 없다. 자식이 모두 재정의해야 객체가 된다. 일반 가상 함수는 부모에 기본 구현이 있어 재정의하지 않아도 된다.

C#의 abstract 메서드와 virtual 메서드의 관계와 같다고 보면 된다. 다른 것은 C++에 abstract라는 키워드가 없고 = 0이 그 자리를 대신한다는 점뿐이다.

struct와 class의 차이도 C#과 어긋나는 자리다. C++에서 둘은 기능이 같고 멤버와 상속의 기본 접근 권한만 다르다. 기본 접근 지정자가 struct는 public, class는 private이고, 둘 다 멤버 함수와 상속, 가상 함수를 가질 수 있다.

할당 위치는 지역 변수로 선언했는지 new로 만들었는지가 정한다. C#에서 struct가 값 형식, class가 참조 형식으로 의미가 크게 다른 것과 대비된다.

부모가 둘이면 할아버지가 두 벌 생긴다

C++은 클래스 다중 상속을 허용한다. B와 C가 A를 상속하고 D가 B와 C를 함께 상속하면 D 안에 A의 멤버가 두 벌 생겨 어느 쪽인지 모호해진다. 다이아몬드 문제라고 부르는 것이 이것이다.

class B : virtual public A처럼 가상 상속을 하면 공통 조상 A가 한 벌만 남아 모호함이 사라진다. C#은 클래스 다중 상속을 막고 인터페이스만 여럿 구현하게 해 이 문제를 아예 피한다.

캐스트 네 개를 C#과 짝지어 둔다

실행 중에 객체의 실제 타입을 알아내는 기능을 RTTI라고 부르고 dynamic_cast와 typeid가 이를 쓴다. 타입 정보가 가상 함수 테이블에 연결돼 있어, 부모에 가상 함수가 하나도 없으면 다운캐스트용 dynamic_cast를 쓸 수 없다.

실패하면 포인터는 nullptr, 참조는 std::bad_cast 예외를 낸다. 검사 비용이 있어 잦은 호출은 피한다.

static_cast는 컴파일 타임 변환이라 잘못된 다운캐스트를 막지 못하고, reinterpret_cast는 비트를 그대로 재해석하는 저수준 변환이다. const_cast로 const를 뗐더라도 원래 const로 정의된 객체를 수정하면 정의되지 않은 동작이다.

면접에서 이렇게 답한다

  • 가상 함수는 어떻게 동작하나 — 클래스마다 함수 주소 표인 vtable이 하나 생기고 객체에는 vptr이 들어간다. 호출할 때 vptr을 따라가므로 부모 포인터로도 자식 구현이 불린다고 답한다.
  • 가상 소멸자는 왜 필요한가 — 부모 포인터로 delete할 때 virtual이 아니면 정의되지 않은 동작이고 자식 소멸자가 불리지 않는다. 다형적으로 쓸 기반 클래스는 소멸자를 public virtual로 둔다고 규칙까지 말한다.
  • struct와 class의 차이는 — C++에서는 기본 접근 지정자만 다르다. 스택인지 힙인지는 지역 변수인지 new인지가 정하며, C#의 값 형식 구분과는 다른 이야기다.
  • 생성과 소멸 순서는 — 생성은 부모부터, 소멸은 자식부터다. 부모 생성자가 도는 동안에는 자식이 없어 그 안에서 부른 가상 함수는 부모 버전이 불린다.

이런 오해를 한다

  • “vtable은 객체마다 하나씩 들어간다” — 표는 클래스당 하나다. 객체가 갖는 것은 그 표를 가리키는 포인터 하나다.
  • “자식에 같은 이름 함수를 만들면 재정의된다” — 부모에 virtual이 없으면 가리기다. 부모 포인터로는 부모 함수가 불린다.
  • “생성자에서 가상 함수를 부르면 자식 버전이 불린다” — 그 시점에는 자식이 없다. 초기화가 끝난 뒤 따로 부르게 설계한다.
  • “C++ struct는 값 형식이라 스택에 잡힌다” — C#과 섞은 오해다. new로 만들면 struct도 힙에 잡힌다.

3줄 정리

  • C++은 virtual을 붙여야 재정의가 된다
  • vtable은 클래스당 하나, 객체엔 포인터 하나
  • 부모 포인터로 지울 거면 소멸자도 virtual
